## Lessons & Pitfalls 经验与坑

**坑（最重要）：`switch` 里的重复 `case` 是静默死代码，工具链全都不报**
我在 `applyProjection` 新加 `case "contextPressure"`（占用条口径）时，旧的同名 case
（同步模型胶囊的 `contextWindow`）还在下面 → 后者**永远不会执行**，
那件事被静默丢掉。`npm run typecheck` 通过、24 套断言通过，只有 `npm run build`
的 esbuild 警告 `[duplicate-case]` 抓到了它。
→ 长 `switch`（`applyProjection` 有 20+ 分支）改动后**必须看 build 的警告**，
不只是看 typecheck 绿不绿。已加 `scripts/invariants.test.ts` 钉住。

**坑：我声称「已处理」的东西其实没处理——要验证，不要相信自己的记忆**
我告诉子代理「那 8 个 `@key` 标记都已处理」，实际**6 个没有**（3 个完全没词条、
3 个有词条但没 `resolveText` case）。子代理逐条核对后纠正了我。
→ 移交 / 协作时给出「已处理」清单，**要么附验证据，要么让接收方自己验**。

**坑：重复的对象键在 JS 里不报错，后者静默覆盖前者**
往 `test/preview.html` 插附件夹具时我留了两个 `attachments:` 键 → 调样式时看到的是
被覆盖后的那份（或旧的那份），而语法完全合法。已加断言扫「同一对象内重复键」。

**坑：CSS 特异性相同、后者胜——`.is-stop` 吃掉了 `:hover`**
`.send-btn:hover` 与 `.send-btn.is-stop` 特异性都是 0,2,0，而 `.is-stop` 在后面，
于是悬停色整个失效 = 「鼠标移上去没反应」。修法是给 `.is-stop:hover` 单独一条规则
（顺带染成错误色：停止是破坏性动作）。
→ 「同一元素的状态类覆盖了伪类」这类问题，**写规则时就要算特异性**，别指望看出来。

**坑：用「含空白」判断是不是路径，会误伤带空格的目录**
第一版 `looksLikePath` 用「含空白 → 不是路径」，于是 `src/sub/odd name/x.ts` 被判成
命令行——而它是真路径，文件名会被右省略切掉（**正是本次要修的问题**）。
正解看**首个 token**：路径的分隔符出现在空白之前，命令行的程序名不含分隔符。
→ 启发式判据要用**能区分两类样本**的特征，不是「看起来像」。我自己写的测试抓到了这条。

**坑（重要）：把用户的需求读反了方向——「不要空着」被我做成了「拿不到就清空」**
用户报「占用率卡着不动」，我先入为主认定「显示旧值」是病根，
于是把 `refreshOccupancy` 改成拿不到分子时**清空**。用户立刻纠正：
**要常驻显示**，没刷新时**保留旧值**，真正的病根是「好几轮都没刷新」。
→ 教训与上一次「鲸鱼变蓝」同源：**用户描述现象时，别急着认定哪一半是 bug**。
   这次正确的读法是「刷新机制坏了」而不是「显示策略坏了」。
   → 规避（也是 `AGENTS.md` 里那条的老调）：**先把事实测出来再改**。
     这里测出来的事实是「投影的分子要等下一次请求才出现」+「我砍掉了每轮的刷新触发点」，
     两条一摆，改法就唯一了。我第一轮没测就改，白绕一圈。

**坑：`feedUsage` 喂合成字段会被静默忽略**
写占用测试时给 `assistant/message` 喂了 `{cachedTokens: 1152}`——那是 `UsageView`
的字段；而 `toUsage` 只读**线格式**的 `cacheReadTokens`/`cacheWriteTokens`，
于是本地复算少算了缓存，断言差 1000 才暴露。
→ 造测试夹具时要分清**线格式**与**视图模型**两层；类型都是可选的数字字段，编译器不会拦。

**实测有效的做法：`inputTokens + cachedTokens` 与官方 `pressureTokens` 逐字相等**
```
usage = {inputTokens:18054, cacheReadTokens:1152, cacheWriteTokens:0, totalTokens:19208}
本地 input + cached = 19206
官方 pressureTokens  = 19206   ← 逐字相等
totalTokens          = 19208   ← 含 output，差 2
```
所以投影缺分子时用它是**同口径兜底**，不是「自己另算一个」。
（而 `totalTokens` 才是不能用的那个：含 output、压缩后还不降。）
→ 这条把「要不要本地兜底」从一个口味问题变成了一个**可验证的等式**，
   探针里就有一条断言钉着它（`scripts/pressureProbe.ts`）。

**坑：探针窗口太短会造成「假失败」，而假失败比真失败更贵**
`queue-esc-e2e` 一次跑出 3 项失败（队尾没被接续），复跑一次全过 —— 队首那轮让模型
**真的干活**，耗时随模型/工具波动，90s 窗口不够。断言语义没错，错的是窗口。
→ 断言真实模型延迟的 E2E，窗口要按**最坏情况**给（已改成 180s 并写明理由）；
   看到 E2E 失败**先复跑一次**再下结论。

**坑：探针的断言不能比现象更确定**
`queueContinueProbe` 第二轮（中止后再提交会不会唤醒队列项）在**同一脚本的三次运行**里
得到 0/3、0/3、3/3。第一版断言写成「队列项在任何一次试验里都没丢」，在 0/3 那轮假失败。
→ 只对**确定性**事实硬断言，不确定的那条作为**观察分布**打印，并在注释里写明
   「同一脚本另一次运行结果相反」——那才是「客户端无法预判」的证据本身。

**坑：`vscode.l10n` 的 bundle 用**英文原文**当 key**
`l10n/bundle.l10n.zh-cn.json` 的键是**英文源串**、值是中文；不是把中文当键。
另外 `package.json` 必须有 `"l10n": "./l10n"`，**否则 bundle 根本不会加载**
（本次该字段此前不存在，是子代理补的）。

**坑：`.vscodeignore` 没写的东西会进 vsix**
`AGENTS.md` 第一次打包时进了发布包（5.5 KB）。它是给 AI 会话用的项目文档，
不是扩展的一部分。已加进 `.vscodeignore` 并重新打包确认 14 个文件。

**有效做法：先读 `.d.ts` 契约、再用 E2E 核对「真实形状」**
`goal` 的嵌套形状是 E2E 从真实投影打出来才敢写死的；`plan` 的 `pending` 语义是
E2E 抓到「裸读 active 会看起来没反应」。两份契约**读了不算完**。
→ 具体路径：先读 `lib/types/**/*.d.ts`（短、可读），再回 `lib/client.js` grep 确认，
   有疑问写探针实测。

**有效做法：给子代理派活时，把「它不该碰的文件」明确列出来**
本次两个子代理并行改同一批文件（`controller.ts`），其中一个主动报告了 mtime 变化并
停下来问——避免了互相覆盖。协作前先划文件所有权。
另外子代理**不受会话内的文件观察规则约束**，它读到的可能是你正在改的中间态。

**关于 #17（停止语义）——这是与官方契约的刻意偏离，不是遗漏**
官方契约说 cancel 后排队工作按 FIFO 继续、UI 只发一次 cancel。
实测（`node build/queue-continue-probe.mjs`）**只 cancel 不会让队列自行接续**（两轮 3/3），
而「之后再提交新消息会不会唤醒队列项」**不稳定**（同一脚本 0/3 vs 3/3）。
所以保留「摘空队列 → cancel → 等空闲 → 按原序重发」：让 ESC 的行为由客户端决定。
取舍已写进 README「已知限制」与 `docs/audit-summary.md` §零。

## Constraints 约束与注意

- **git**：commit 一律中文描述；**未经用户明确说「提交」不得 commit**。
- **构建/测试一律经 `build` 工具**（`pwsh` 沙箱下 esbuild 会 `spawn EPERM`、
  探针写 `~/.dsh` 会 `EPERM`）。标准命令：`npm run typecheck`、`npm test`、
  `npm run build`、`npm run smoke`、`npm run package`；
  端到端探针：`node build/command-e2e.mjs`、`node build/queue-esc-e2e.mjs`、
  `node build/queue-continue-probe.mjs`；界面看 `npm run preview`（`?locale=en` 看英文）。
- **新增测试必须登记到 `esbuild.scripts.mjs` 的 `entries`**，否则 `npm test` 静默不跑。
- **双语是硬规则**，见 `AGENTS.md`：宿主里的用户可见文案**不许写死中文**——
  交给 webview 的用 `@key`，交给 VS Code 的用 `vscode.l10n.t` + `l10n/bundle.l10n.zh-cn.json`。
  加 `@key` 必须补齐 `texts.ts` 的接口 + **zh 与 en 两个字典** + `resolveText` 的 case。
- **不要编造数据**：预览夹具、测试数据、文档里的形状都必须来自真实输出
  （`scripts/previewFixture.test.ts` 会检查夹具能被求值）。
- **`processRegistry` 是异步的**：`scanServers` / `cleanupResidualServers` /
  `clearStaleDocumentLocks` 都必须 await。
- **协议事实**：`session/cancel` 不让队列续跑；`steer` 要求 `status === 'running'`；
  重发必须换新 `requestId`；`session/page` 的 `throughSeq` **必须**来自同一次
  `session/follow` 的 `snapshot.cursor`；`session/fork` 的 `atSeq` 必须落在 `turn/end`
  （开放轮里锚定会被**拒绝**而不是往前裁剪）。
- **投影优先于历史事件**：`follow()` 的 onItem 里回放必须在铺投影**之前**，
  `scripts/projections.test.ts` 有源码级断言。
- **`plan` 的生效值必须用 `planModeFromProjection`**，不要重写 `Boolean(value.active)`。
