## Lessons & Pitfalls 经验与坑

**坑（本轮最重要）：投影有「已落日志」与「已选择但未落日志」两个字段，只读前者会漏**
`plan` 投影是 `{active, pending}`：`active` 是最后一条 `plan/mode`，`pending` 表示有一次
`/plan` 选择指向与 active 不同的目标、还没被记录。**生效**状态是
`pending ? !active : active`。轮次进行中发 `/plan` → 服务端回
「Entering plan mode (applies from the next step).」，投影是 `{active:false,pending:true}`
——裸读 `active` 会让「进入计划模式」按钮看起来毫无反应（用户再点一次，而契约里那是 no-op）。
[实测] `scripts/commandE2E.ts` A 组把这条路径完整跑到了。
→ 规避：契约里凡是「wanted/pending/target + 已提交值」成对出现的状态，生效值通常是两者的
组合，别只读一个。官方 chip 用的就是 `pending ? !active : active`（`dsh-client-ui-plan/lib/client.js:47`）。

**坑：快照回放顺序会静默覆盖折叠值**
`follow()` 原来**先铺投影、再回放记录**。投影是「截至 `asOfSeq` 的折叠结果」，永远比记录里
的历史事件新；反过来做，历史里最后一个事件会把界面状态覆盖回旧值。`plan` 是活例：轮次中发的
`/plan` 日志里没有对应 `plan/mode`，重开会话时末尾那条旧 `plan/mode` 会把计划模式关掉。
→ 已改为**先 `adapter.applyFrame`、再 `applyProjection`**，并用源码级断言钉住顺序
（`scripts/projections.test.ts` 扫描 `followSession` 的 `onItem` 回调）。

**坑：`commands/execute` 对不存在的命令返回 `undefined` 而不是报错**
`request<CommandExecution | undefined>` 的 `value === undefined` 表示「没有这条命令」。
命令节点只由 `command/run`/`command/done` 折出，**没进处理器就没有节点**，所以这条路径要
单独补提示（`@unknownCommand:`）。

**坑：手打命令的识别不能只按「有斜杠」**
官方 enter 列的规则是：行首 `/` + 非空名字 + 名字在目录里；**带参数**时还要求该命令声明了
自由输入（`input` 描述符）。不满足就按普通消息发出去——否则打错的 `/foo` 会被吞掉，
用户以为模型没收到。

**坑：`/plan` 与「正文前缀」的区别必须靠实测而不是读代码**
`commands/execute "/plan"` 与「正文写 `/plan xxx`」在同一台服务器上行为完全不同，且**文案会变**
（空闲时 `Plan mode on.`，轮次进行中 `Entering plan mode (applies from the next step).`）。
单看一次运行的返回值会得出错误结论——本轮第一次 E2E 拿到 `Plan mode on.`、第二次拿到
`Entering...`，两次都对。

**坑：探针的断言不能比现象更确定**
`queueContinueProbe` 第二轮（中止后再提交新消息，看会不会唤醒保留的队列项）在同一份脚本的
**三次运行里得到 0/3、0/3、3/3** 三种结果。第一版我写成「队列项在任何一次试验里都没有丢」
和「新消息不会抢在前面」，前者在 0/3 那轮因为「两条都没跑到」而假失败。
→ 现在只对**确定性**的事实硬断言（只 cancel 不接续，两轮都 3/3），把不确定的那条作为
**观察分布**打印，并在注释里写明「同一脚本另一次运行结果相反」——这才是「客户端无法预判」
的证据本身。

**坑：新增测试必须同时登记到 `esbuild.scripts.mjs`**
`npm test` 的 runner 只发现 `build/*.test.mjs`，而 `build/` 由 `esbuild.scripts.mjs` 的
`entries` 生成。只写 `scripts/xxx.test.ts` 会静默不跑（本次新增 3 套都登记了，
runner 显示 18/18）。

**坑：`build` 工具不接受 `run_in_background`**
参数会被忽略、命令仍在前台跑。要做长时间探针就直接从前台发起并给足 `timeoutMs`
（`queue-continue-probe` 单轮约 3 分钟，`command-e2e` 约 1 分钟）。

**有效做法：先读 `.d.ts` 契约、再用 E2E 核对「真实形状」**
两份契约读了不算完——`goal` 的嵌套形状是 E2E 从真实投影里打出来才敢写死的
（真实值：`{"goal":{...,"maxGoalRounds":256},"roundsStarted":0,"createdAt":...,"updatedAt":...}`，
`maxGoalRounds` 默认 **256**）。审计的原始教训就是「按猜测的形状写」，本轮把它倒过来做。

**有效做法：给新 UI 留可核对的夹具**
`test/preview.html` 里新增的目标条、命令节点、轮尾文件行，取值**逐字抄自 E2E 实测输出**
（不是编的），并在注释里标明来源。`npm run preview` 可直接肉眼核对样式。

## Constraints 约束与注意

- **git**：commit 一律中文描述；**未经用户明确说「提交」不得 commit**。
- **构建/测试一律经 `build` 工具**（`pwsh` 沙箱下 esbuild 会 `spawn EPERM`、
  探针写 `~/.dsh` 会 `EPERM`）。标准命令：`npm run typecheck`、`npm test`、
  `npm run build`、`npm run smoke`、`node build/command-e2e.mjs`、
  `node build/queue-continue-probe.mjs`、`npm run e2e:queue-esc`。
- **新增测试要登记到 `esbuild.scripts.mjs` 的 `entries`**，否则不会被 `npm test` 发现。
- **不要编造数据**：预览夹具、测试数据、文档里的形状都必须来自真实目录/真实事件
  （本轮目标条与命令节点的夹具值抄自 `commandE2E.ts` 的输出）。
- **`processRegistry` 是异步的**：`scanServers()` / `cleanupResidualServers()` 返回 Promise，
  新增调用点必须 await。
- **协议事实**：`session/cancel` 不让队列续跑；`steer` 取消后不可用；重发必须换新 `requestId`。
- **`plan` 的生效值必须用 `planModeFromProjection`**，不要在任何地方重新写
  `Boolean(value.active)`——那正是本轮修掉的 bug。
- **投影优先于历史事件**：`follow()` 的 onItem 里回放必须在铺投影**之前**，
  `scripts/projections.test.ts` 有源码级断言，改顺序会让测试失败。
