# 消息、工具与交付显示

修改 durable 消息、工具行、产物卡片、Markdown 路径或文案登记前读本文。线格式见[服务端契约](<dsh-server-api.md>)，提交与乐观回显见[发送设计](<design-draft.md>)，图片读取见[安全边界](<design-security.md>)。

## 用户消息与引用身份

用户正文、图片和文件块均须保留，不能按文本是否非空过滤整条消息或内容块。durable `user/message.data` 就是消息本体，不包 message；它与 system/message、tool/result 的包装不同。

消息里的**附件芯片**是单击打开的入口，解析链与落地见[附件设计](<design-attachments.md#打开附件>)；悬停显示原文件完整路径，那份路径由宿主按内容身份查出来交给适配器（`adapter.userMedia` 的 `originalPathFor`），查不到就不给提示。**图片缩略图不是**打开入口：它单击出来的仍是原图浮层，与助手消息、工具行、正文外链的图共用同一套待遇。

会话引用进入模型前变成快照，durable 正文折成 `@标题`，会话 id 由紧随的 session-reference 召回事件补回，按 seq - 1 关联用户消息。复制与提问预览使用可读标题，不能把会话引用误判成路径；补全 token 规则见[引用设计](<design-mentions.md>)。

## 正文链接的悬停与浏览器打开

普通正文相对文件链接按会话创建目录解释，工具行 / 产物使用各自判据选出的目标，行内代码可由本轮操作的参数别名匹配记录路径。悬停与点击共用同一目标；已有绝对目标时悬停给出完整路径，拿不到创建目录时只保留原样拼写、不冒充绝对位置；外链给出完整地址。文件芯片、本轮改动行与交付行同样以目标路径作悬停首行，芯片上只画文件名。记录值、别名判歧义、执行世界访问与验证边界统一见[文件路径](<design-paths.md>)。

外链由扩展的 `openExternal` 帧交给系统，系统按受信域名决定是否先问一次，**一次点击只走这一条**。正文锚点的点击因此必须 `stopPropagation`：VS Code 的 webview 外层页本身还挂着 click 监听，会把同一个锚点再转成一次 `did-click-link`，而且不检查 `defaultPrevented`；两条都跑就是一次点击打开两次。页内锚点（`#…`）仍放行给外层页滚动。

HTML 家族（`.html` / `.htm` / `.xhtml` / `.shtml`）的文件链接有 `Ctrl/Cmd` 单击系统浏览器打开入口；普通单击仍由 VS Code 承接。markdown 锚点、行内代码文件链接与已发出的 `@文件` 引用共用修饰键判据（`browserOpenRequested`）与扩展名白名单（`shared/webFile.ts`）；宿主收到 `openFileInBrowser` 后再验白名单。该入口通过 Host 的原生能力打开，由 Host 验证执行世界到桌面的文件映射；不能把远端路径直接交扩展本机浏览器，能力不可用时明确提示。文件芯片与本轮改动行的 `Ctrl/Cmd` 仍表示「直接打开文件、不要 diff」，不叠加浏览器行为。

## 改动对比的来源

文件芯片与改动卡片默认「看改动」。只要带得动**本轮坐标**（`ChangeCoordinates`：`seq` / 清单下标 / 轮号），宿主先向 Host 取 `GET /api/changes.diff`，用这一轮的 turn-start / turn-end 快照开 VS Code 原生对比窗口——**提交之后仍然看得到**，因为这份数据不依赖工作区是否还脏。坐标只由改动卡片与能在清单里证明同一目标的芯片行发出，不按路径拼写猜；没有坐标的入口直接按执行世界打开文件，不查本机 Git 的改动状态。对比开不出来时落到普通打开，打开目标不可用时按文件三态给提示，两条路都不静默。

Host 只给 hunk，两侧文本由 `changesDiff.ts` 拼：整份新建 / 删除 / 粗粒度直接拼整侧；两边都在时先用**同一执行世界**读到的当前文件逐行核对每个 hunk 的 new 侧，对得上才回填 turn-start 全文，对不上就退化成带省略标记的片段（标题注明「片段」），不把另一版内容冒充成本轮上下文。当前文件读不到（已删除、权限、离线）时仍用 hunk 片段展示，不从本机同名文件回填。**新文件仍遵旧口径**：文件还在执行世界里时直接打开文件，不显示「空 → 全文」的 diff；只有文件已经不在时才用快照保住内容。旧会话、Host 重启过、二进制 / 过大或载荷形状不合规时没有可用快照，一律退回普通打开（只读资源），不退回本机 Git 对比。回填只核对 hunk 覆盖到的行；本轮之后在 hunk 之外的改动会被并入两侧，所以右侧是当前文件内容而不是 turn-end 快照，这份对比表达的是「把本轮改动应用到当前文件」。

清单根内相对 / 根外绝对、规范化根及坐标关联规则见[文件路径](<design-paths.md>)。

点击前那一段等待来自 `GET /api/changes.diff`（Host 要现算 hunk，可能还要读两侧快照），所以宿主按 `(连接, 会话, seq, 下标)` 做 fetch-once 缓存并合并同坐标的 in-flight 请求；改动卡片行在**悬停 / 键盘聚焦**时先发 `prefetchChanges` 只取数、不打开编辑器，真正点击时直接命中。打开日志带总耗时与取数耗时，便于分辨慢在取数、读盘还是编辑器启动。缓存随连接切换整体作废（seq 只在同一条连接里有意义），并有条数上限。

## 交付文件与工具产物

`present` 申报与 write / edit 派生的本轮产物有独立显示入口。工具产物、命令流程节点与模型正文是不同来源，不能用“正文里已经提到”代替产物登记。

当前由 `produced.ts` 从成功第一方变更调用派生参数路径，再由 `mutationResultPath` 按记录值与参数是否绝对决定产物目标，并保留操作参数别名，供正文行内代码唯一匹配目标；工具行、产物与终端三套判据各自独立，规则见[文件路径](<design-paths.md>)。命令节点与交付卡片分别保持各自身份，文件去重不能吞掉独立交付入口。正文图片经执行世界受认证读取，不以扩展名或创建目录包含性准入，字节限额由服务端媒体路由裁决，见[安全边界](<design-security.md>)。

## 问卷作答与会话切换

待答问卷由输入区接管，已收场的问卷留在消息流里当记录；选举与抑制规则见 `pendingInteraction.ts`，卡片形态与自定义回答规则见 `Rows.tsx` 的 `QuestionCard`。

填写中的选项、自定义文本、自定义回答的选中态与依次问答的停靠题位属于**界面草稿**，由 `questionDraft.ts` 按「会话 id + 问卷 requestId」存在 webview 内存里。切走会话后卡片卸载，切回来按同一把键恢复；切换轨迹、抽屉等不卸载输入区的路径不受影响。草稿**不落盘、不进宿主的 drafts / pendingMessages 账本**：DSH 重启或 webview 重载后待答问卷本就要重新发起，保留半份答案没有意义。问卷收场（已作答 / 已撤回）时清掉对应草稿，内存表另有条数上限，超出按写入先后淘汰。

已答完的记录**只读 `question.answers`**，不能拿本地草稿充当「用户当时选了什么」：另一个窗口作答、重载与切回会话时本地草稿是空的。草稿只负责「还没答完的那张卡」，两者不能合并成一份状态。

## 工具状态与事件消费

- 中止轮次必须结算在飞工具，避免永久显示运行中。结果找不到调用时保留孤立结果卡片，不静默丢弃；max-tokens 收尾已有单独提示。
- 活性与工具种类分开：有 tone 不代表应遮掉工具图标，未知子代理活性不画确定状态点。
- 每个工具展开内容各持自己的 ref，diff、划选与回顶不能共用最后一个节点。
- 已知但不渲染的事件列入显式白名单，未知且不可忽略的实时事件才进入黄色[消息通知](<design-notifications.md>)；历史重放不补提醒。类型登记、实际消费与有意忽略分别维护，不能用白名单掩盖应消费状态。内核新增事件词汇工具看不见，每次对齐版本按[版本兼容](<dsh-compat.md>)的「词汇漂移」人工求一次差。
- 会话正文中的通知段与顶部通知队列是两条不同展示路径。正文、卡片或局部原位已明确承接的失败，不再额外加入通知队列；不将历史正文通知搬入队列。
- 会话快照 / patch 字段和 JSON 清空规则见[投影设计](<design-projections.md>)，不用本地另一份字段表修补显示。
- 读 / 写 / 编辑节点按住 `Ctrl/Cmd` 单击直接打开本次调用操作的文件（普通单击仍是开合节点）：读取节点在本次读取带行号区间时打开到起始行，编辑节点没有行号数据，只打开文件。技能节点同样打开对应的 `SKILL.md`；悬停只要真有可打开目标就追加一行修饰键提示。技能路径只取服务端 `skills/list` 的 `path`（随当前会话命令目录下发），缺失时不挂动作、不提示、也不按名字拼本机路径。技能节点的展开体只显示 `<skill_instructions>` 正文，不显示参数与「输入 / 输出」标题。
- 可打开文件的节点在**鼠标悬停**或**按住 `Ctrl/Cmd`** 时给路径加下划线（只是手势提示，单击行为不变）：悬停这一档不依赖键盘焦点，按住修饰键这一档由根元素上的 `is-modifier-held` 类驱动，避免为一次按键重渲染整棵消息树。

## Windows 路径链接

CommonMark 把反斜杠加 ASCII 标点视为转义，会吞掉 Windows 绝对路径中点目录等分隔符。`linkDestinations.ts` 在 tokenizer 层保留原目标，将 Windows 绝对路径中的反斜杠编码为 `%5C`，由 fileLinks / imageRef 解码；这是刻意偏离官方同类解析行为的修复。

只修行内链接与图片的目标，不改链接标签、裸路径文本、参考式定义或非 Windows 目标；括号配平等分歧保持默认解析。保住 UNC 文本不等于允许访问远端，宿主准入仍拒绝 UNC。Markdown 渲染正确与文件 / 图片可安全打开是两个边界。

## 中文标点收尾的加粗

CommonMark 的定界符 run 规则要求闭合 `**` 是 right-flanking，`…不够。**分页…` 这种「前是中文标点、后紧跟汉字」的收尾不满足，星号会当字面文本露在正文里（同一段里闭合符后是换行或标点的加粗照常生效，所以看着像模型写错了标记）。官方渲染链用 `cjkFriendlyStrong` 扩展放宽这条规则，`cjkStrong.ts` 在 tokenizer 层补上同一判据：星号数 ≥ 2、前一字符是 Unicode 标点、后一字符属 CJK 文字系统。这一条是**向官方对齐**，与上一节的刻意偏离不同。

只放宽正好两个星号的 `**`，且只在默认解析找不到闭合时生效；西文相邻、单星号 em、三星号组合、代码里的星号一律保持 marked 原语义。

## 文案登记完整性

工具标题、宿主 `@key` 标记与中英词典须双向完整。参数文案用登记函数，不能拼接句子，也不能用宽泛类型断言与裸 id 回退掩盖缺项。

`resolveText()` 仅翻译标记，模型与服务端原文不翻译；原生通知、VS Code 清单与 webview 词典各遵守[双语约定](<../AGENTS.md>)。用户可见语义提示须中英同时登记，未知或未验证状态不能显示为确定成功。

## 回归入口

produced、commandNode、references、thinkingStream、unknownEvent、markdown、i18n 与 styles 覆盖对应链路；本地图片另见 localImages / imageHydrate。离线断言固定确定事实，不能将无异常、预览可见或文案完整推广为系统剪贴板、安装端 IPC 或全部事件时序已验证。
