# 消息、工具与交付显示

修改 durable 消息、工具行、产物卡片、Markdown 路径或文案登记前读本文。线格式见[服务端契约](<dsh-server-api.md>)，提交与乐观回显见[发送设计](<design-draft.md>)，图片读取见[安全边界](<design-security.md>)。

## 用户消息与引用身份

用户正文、图片和文件块均须保留，不能按文本是否非空过滤整条消息或内容块。durable `user/message.data` 就是消息本体，不包 message；它与 system/message、tool/result 的包装不同。

消息里的**附件芯片**是单击打开的入口，解析链与落地见[附件设计](<design-attachments.md#打开附件>)；悬停显示原文件完整路径，那份路径由宿主按内容身份查出来交给适配器（`adapter.userMedia` 的 `originalPathFor`），查不到就不给提示。**图片缩略图不是**打开入口：它单击出来的仍是原图浮层，与助手消息、工具行、正文外链的图共用同一套待遇。

会话引用进入模型前变成快照，durable 正文折成 `@标题`，会话 id 由紧随的 session-reference 召回事件补回，按 seq - 1 关联用户消息。复制与提问预览使用可读标题，不能把会话引用误判成路径；补全 token 规则见[引用设计](<design-mentions.md>)。

## 正文链接的悬停与浏览器打开

正文里的本地文件链接悬停给出**完整路径**（按会话工作目录归一，拿不到 cwd 时保留链接上的原样拼写），外链给出完整地址。文件芯片、本轮改动行与交付行同样以完整路径作悬停首行，芯片上只画文件名。

HTML 家族（`.html` / `.htm` / `.xhtml` / `.shtml`）的本地文件链接支持按住 `Ctrl/Cmd` 单击用系统浏览器打开；普通单击仍交给 VS Code 按资源类型打开。markdown 锚点、行内代码文件链接与已发出的 `@文件` 引用共用同一条修饰键判据（`browserOpenRequested`）与同一份扩展名白名单（`shared/webFile.ts`）；悬停里追加一行修饰键提示。宿主收到 `openFileInBrowser` 后按同一口径解析路径并**再验一次白名单**，不存在或系统拒绝时明确告知。文件芯片与本轮改动行的 `Ctrl/Cmd` 已有「直接打开文件、不要 diff」的含义，不叠加浏览器行为。

## 交付文件与工具产物

`present` 申报与 write / edit 派生的本轮产物有独立显示入口，图片经受限本地读取显示。工具产物、命令流程节点与模型正文是不同来源，不能用“正文里已经提到”代替产物登记。

成功第一方变更调用由 `produced.ts` 派生本轮文件，命令节点与交付卡片分别保持各自身份；文件去重不能吞掉独立交付入口。

## 问卷作答与会话切换

待答问卷由输入区接管，已收场的问卷留在消息流里当记录；选举与抑制规则见 `pendingInteraction.ts`，卡片形态与自定义回答规则见 `Rows.tsx` 的 `QuestionCard`。

填写中的选项、自定义文本、自定义回答的选中态与依次问答的停靠题位属于**界面草稿**，由 `questionDraft.ts` 按「会话 id + 问卷 requestId」存在 webview 内存里。切走会话后卡片卸载，切回来按同一把键恢复；切换轨迹、抽屉等不卸载输入区的路径不受影响。草稿**不落盘、不进宿主的 drafts / pendingMessages 账本**：DSH 重启或 webview 重载后待答问卷本就要重新发起，保留半份答案没有意义。问卷收场（已作答 / 已撤回）时清掉对应草稿，内存表另有条数上限，超出按写入先后淘汰。

已答完的记录**只读 `question.answers`**，不能拿本地草稿充当「用户当时选了什么」：另一个窗口作答、重载与切回会话时本地草稿是空的。草稿只负责「还没答完的那张卡」，两者不能合并成一份状态。

## 工具状态与事件消费

- 中止轮次必须结算在飞工具，避免永久显示运行中。结果找不到调用时保留孤立结果卡片，不静默丢弃；max-tokens 收尾已有单独提示。
- 活性与工具种类分开：有 tone 不代表应遮掉工具图标，未知子代理活性不画确定状态点。
- 每个工具展开内容各持自己的 ref，diff、划选与回顶不能共用最后一个节点。
- 已知但不渲染的事件列入显式白名单，未知且不可忽略的实时事件才进入黄色[消息通知](<design-notifications.md>)；历史重放不补提醒。类型登记、实际消费与有意忽略分别维护，不能用白名单掩盖应消费状态。内核新增事件词汇工具看不见，每次对齐版本按[版本兼容](<dsh-compat.md>)的「词汇漂移」人工求一次差。
- 会话正文中的通知段与顶部通知队列是两条不同展示路径。正文、卡片或局部原位已明确承接的失败，不再额外加入通知队列；不将历史正文通知搬入队列。
- 会话快照 / patch 字段和 JSON 清空规则见[投影设计](<design-projections.md>)，不用本地另一份字段表修补显示。

## Windows 路径链接

CommonMark 把反斜杠加 ASCII 标点视为转义，会吞掉 Windows 绝对路径中点目录等分隔符。`linkDestinations.ts` 在 tokenizer 层保留原目标，将 Windows 绝对路径中的反斜杠编码为 `%5C`，由 fileLinks / imageRef 解码；这是刻意偏离官方同类解析行为的修复。

只修行内链接与图片的目标，不改链接标签、裸路径文本、参考式定义或非 Windows 目标；括号配平等分歧保持默认解析。保住 UNC 文本不等于允许访问远端，宿主准入仍拒绝 UNC。Markdown 渲染正确与文件 / 图片可安全打开是两个边界。

## 中文标点收尾的加粗

CommonMark 的定界符 run 规则要求闭合 `**` 是 right-flanking，`…不够。**分页…` 这种「前是中文标点、后紧跟汉字」的收尾不满足，星号会当字面文本露在正文里（同一段里闭合符后是换行或标点的加粗照常生效，所以看着像模型写错了标记）。官方渲染链用 `cjkFriendlyStrong` 扩展放宽这条规则，`cjkStrong.ts` 在 tokenizer 层补上同一判据：星号数 ≥ 2、前一字符是 Unicode 标点、后一字符属 CJK 文字系统。这一条是**向官方对齐**，与上一节的刻意偏离不同。

只放宽正好两个星号的 `**`，且只在默认解析找不到闭合时生效；西文相邻、单星号 em、三星号组合、代码里的星号一律保持 marked 原语义。

## 文案登记完整性

工具标题、宿主 `@key` 标记与中英词典须双向完整。参数文案用登记函数，不能拼接句子，也不能用宽泛类型断言与裸 id 回退掩盖缺项。

`resolveText()` 仅翻译标记，模型与服务端原文不翻译；原生通知、VS Code 清单与 webview 词典各遵守[双语约定](<../AGENTS.md>)。用户可见语义提示须中英同时登记，未知或未验证状态不能显示为确定成功。

## 回归入口

produced、commandNode、references、thinkingStream、unknownEvent、markdown、i18n 与 styles 覆盖对应链路；本地图片另见 localImages / imageHydrate。离线断言固定确定事实，不能将无异常、预览可见或文案完整推广为系统剪贴板、安装端 IPC 或全部事件时序已验证。
