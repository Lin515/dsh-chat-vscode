# 引用补全：查询、抑制、发现范围与候选交接

修改 `@` 触发、目录导航、发现范围、文件 / 会话候选或 `/` 菜单查询前读本文。引用的提交表示见[附件设计](<design-attachments.md>)，平台路径与显示安全见[消息设计](<design-messages.md>)及[安全边界](<design-security.md>)。

## 查询块与浏览入口

光标所在 `@` 内容块由 `findTrigger` / `mentionBlockAt` 判定，查询串取整块，不能随光标在块内的位置变化。普通片段（如 `@web`、裸会话 id）仍可检索会话；候选由服务端按 id / cwd / 标题作大小写不敏感的子串匹配。

裸 `@` 与以 `/` 或 `\` 结尾的路径是浏览入口，恒可展开；目录不存在时显示空表，而不是阻止打开。判据唯一来源为 `shared/mentions.ts` 的 `isBrowseQuery`，宿主和界面共用，不能各维护一份正则。

## 已解析引用抑制补全

普通块是否弹列表由宿主 `controller.mentionResolves` 判断“整块是否已能引用到有效内容”，不是只猜文本形状：

| 内容 | 判据 |
|---|---|
| 文件 / 不带尾分隔符的目录 | 去掉行号区间后 stat；绝对路径原样，相对路径按会话 cwd 解析 |
| `[标题](dsh-session:…)` 或裸 `dsh-session:…` | 解出会话 id，并检查 `this.sessions` |
| 裸 `session-…` id | 不是服务端认可的引用 token，仍属会话检索 |
| 无 cwd、解析失败或未知 stat 错误 | 没有肯定证据，不抑制 |

文件被删 / 改名后可以再次弹出候选。已有目录 `@src` 被抑制，浏览它须写 `@src/`。选中会话插入规范 token `@[标题](dsh-session:…)`。

判定随 `files/list` 的同批 `query` 与 `resolved` 返回。可抑制块不发服务端候选查询，直接回空帧；界面 `mentionSuppressed` 在判定到达前先不弹，避免进入已有引用时闪列表，浏览入口不等待判定。旧宿主不发 `resolved` 时按 false 收，只多弹、不误阻断。

焦点重新进入输入框视为新编辑动作：`onFocus` 清除 ESC / 选中后“已关闭”的记忆并重算触发词。记忆以文本、光标匹配，只依赖文本或光标改变会让原位置重新聚焦永远不弹。

## 键盘只在弹层画出来时接管

界面 `popoverOpen` 是渲染与键盘**共用**的判据（`mentionSuppressed` 与 `popoverVisible` 的合取）：弹层这一帧没画出来时，Enter 归发送、↑↓ 归光标、ESC 交给归属链的兜底。

判据分家会漏出一条隐蔽路径：`rankCandidates` 把 `..` 无条件排在最前，进了目录（有分隔符）就一定有候选，于是“有触发词 + 候选非空”在弹层被抑制时照样为真——抑制门按住的块（例如工作区外的完整路径，宿主判定为已能引用到有效内容）按回车会改写成上一层目录，用户按下的是一个看不见的行。官方 `ui-input-trigger` 的 `arbitrate` 同样以 `state.open` 为前提。

抑制门按住的这段时间里 Enter 会直接发送，而不是静默吞掉：没有画出来的东西不该拦下一键，这也是“弹层没接管 = 发送”的既有口径。

### 关键决策与取舍

只开放裸 `@` 与目录块虽然能避免已有引用弹列表，也会同时禁掉会话 id / 名字片段检索。两种需求无法单靠形状区分，因此保留普通块触发，以宿主的有效内容证据作抑制。未知证据宁可多弹，普通片段重新开启模糊查询是这项选择的结果，不应顺手禁掉。

抑制块可直接回帧；未抑制块需等待查询判定，接受短暂延迟以避免闪烁。官方文件索引仅首次遍历工作区，之后可由陈旧索引当场作答，不把首次成本推广到每次查询。

## 工作区外的发现范围

**状态：已实现**（信任门与 M1 / M2 / M3 三段均已落地，见本节末尾的分段与断言入口）。工作区外发现与补充决策均已确认。开工前先读本节，再动 `fileRefListing.ts` 或候选合成。

### 事实与边界

官方把「引用的书写形态」与「候选的发现范围」分开了：`dsh-file-reference` 的 `FILE_REFERENCE_PROMPT` 明确写着绝对路径指向宿主上的文件或目录（"absolute paths identify files or directories on the host"），而候选发现全部由服务端 `file-reference-local` 提供 —— `WorkspaceFileSearch.list()` 以 agent 工作目录为根，`resolveDisplayDirectory` 对越出根目录或跨卷的展示路径直接判假；官方客户端（web / 终端）只发 `remote.fileReferences.list`，没有一处本地读盘。于是今天的 `@` 列表列不出工作区外的任何条目。

两侧事实使「扩发现」不需要碰协议，也不需要跟官方对齐：

- **越界查询在服务端恒为空**：任何含 `/` 的查询都会走到 `resolveDisplayDirectory` 的越界拒绝；不含分隔符的查询走工作区索引，而索引里只有根目录下的路径。所以越界这一侧**没有服务器行**，本地给出的就是唯一一份清单（`fileRefListing.ts` 文件头那条「本地排序复现不出来就不拼」的限制在这里不成立）。
- **越界引用在本机部署下是真引用**：DSH 的文件沙箱只对写加围栏，读在任何模式都放行（`fs-sandbox` 文件头："Reads pass through untouched: every mode permits reading"）。
- **地基已经有一半**：`missingDirectoryEntries` 已在本机 `readdir` 并按官方同序补齐被截断的目录列举，只差一条包含判据。

边界由此确定：**本地发现只在「执行世界看着就是本机」时才开**（见下一节的信任门——那是一道**启发式**的本地发现闸门，不是远端执行主机的身份认证），只扩**发现**，不改 `@` 的书写形态、不新增 RPC；文件路径的抑制判定复用同一道门，会话引用判定不变。

### 信任门：本机发现的启发式闸门

`@` 的承诺是「执行世界能读到这个路径」。`dshChat.url` 指向别的机器、或 `dshChat.command` 里跑的是 WSL 时，本机列出的路径在那边可能不存在、或是另一个同名文件 —— 那正是 AGENTS 里「引用依赖执行世界能读到本地路径，远端部署下是空头支票」要挡的事。

这道门回答的只是「**要不要**用本机文件系统替 `@` 扩发现」，**不是**「远端执行主机就是本机」的认证：判据是「原生形态 + 同名 cwd 在本机存在」两条**启发式**，远端执行主机上恰好有同形同名的 cwd 时它认不出来（那种部署下两边会混），本扩展也不宣称能识别所有远端部署——代码侧同样注明（见 `localAccess.ts` 文件头）。门由**宿主持有**（界面没有文件系统），两条判据缺一即关：

1. **形状**：服务器报的会话 cwd 必须是宿主平台的原生形态（Windows 宿主：盘符路径 `^[A-Za-z]:[\\/]` 或 UNC；POSIX 宿主：`^/`）。POSIX 形态的 cwd 在 Windows 宿主上直接判假 —— 否则 `Uri.file("/")` 会落到 `C:\`，把远端世界误判成本机。
2. **证据**：该 cwd 在本机 `stat` 出来是**目录**（复用 `fileExistence` 的三态口径，只有明确 `present` 才算，「不确定」按关处理）。

结果按 cwd 串缓存（只缓存**肯定通过**的结果，容量有界），会话 cwd 变化（切会话、换目录）即重算。门关时不补越界条目、不发根目录的「上一层」行；文件路径也不凭本机 `stat` 抑制候选，仍可手写引用并正常发送。会话引用不经过文件系统信任门，继续按会话账本判断。

### 三种入口

| 入口 | 用户写法 | 列的是哪一层 | 写回正文的 token |
|---|---|---|---|
| M1 绝对路径 | `@D:/dev/other/`、`@D:/dev/other/no` | 该目录 / 按筛选词过滤该目录 | `@D:/dev/other/x.txt` |
| M2 根目录「上一层」 | 裸 `@` 那一层多一行「..」 | cwd 的父目录（绝对形态） | `@D:/dev/` |
| M3 相对向上 | `@../`、`@../no` | 相对 cwd 解析，允许越出 | `@../x.txt` |

补充口径：

- M1 的**盘符裸写**（`@D:`）按 `D:/` 列盘根：不这样归一，用户得到的是一句误导性的「没有匹配的文件」。
- M2 只在查询为空串、门通过、且 `dirname(cwd)` 在本机是目录时由宿主下发，作为 `items[0]`（形状 `{ path, kind: "directory", parent: true }`，与界面自己合成的 `..` 同一族，**界面不需要新字段**）。cwd 就是盘根时不发；父目录是盘根时照发（`@D:/` 是可浏览的一层）。
- M3 只认含 `..` **段**的相对查询；相对形态最多退到根（盘符根 / UNC 共享根 / POSIX 根），要列根「以上」的东西只能改用绝对形态。界面算「上一层」时按**会话 cwd 的深度**做段算术（cwd 由 `files/list` 下发）：`../` → `../../`、`../other/` → `../`、`foo/../` 先归一到 cwd 本身所以它的上一层是 cwd 的父目录；退到根就停，查询串不再加长（`../../../` 与 `../../` 在根上是同一层）。没有 cwd（旧宿主 / 还没绑定会话）时不肯把纯 `..` 串加长，退回老口径（上一层是工作区根时仍给空串）。输出一律正斜杠形态——`@` 引用本身就是正斜杠语法，写回正文那条路（`drillQueryToken`）也会归一。
- **不支持的根 / 盘符形态不做本地解释**：Windows 宿主上的单根相对（`/foo/`）、驱动器相对（`D:foo/`）、设备 / 扩展长度命名空间（`\\?\`、`\\.\`）与不完整 UNC（`//server/`），以及 POSIX 宿主上的盘符 / 设备写法，在 `listingTarget` 的**纯字符串判据**处就判假（三条路都不走，一次 FS 调用都不发）；`mentionResolves` 同样不把它们 join 到 cwd。否则 `win32.resolve` 会按当前盘解释 `/foo/`、按 D 盘当前目录解释 `D:foo/`，而 `join(cwd, "/foo")` 拼出的 `cwd/foo` 会让本机同名文件误抑制工作区外的引用。普通相对路径与合法的盘符绝对 / 完整 UNC 不受影响。
- **盘根的 `..` 保留今天的取值**：`mentionParent` 对 `D:/`（以及 UNC 共享根、POSIX 根）返回空串（跳回工作区根）。它是键盘上唯一一条「从盘根回工作区」的回路，隐藏它只能靠重打路径；代价是这个语义在「盘根没有上一层」上不严格，属于刻意取舍。

### 路径解析：放开哪一条、保留哪一条

越界列举的新判据（`resolveListingDirectory`，取代越界分支里的 `resolveInside`；不支持的根 / 盘符形态在更早的纯字符串判据处就被拒绝，走不到这里，见上面「补充口径」）：

- 目标目录按宿主形态是**绝对路径** → 直接用作列举根（不做 `relative()` 包含判据，绝对形态天然可跨卷）；
- **相对且不含 `..` 段** → 仍是今天那条 `resolveInside`（逐段 `lstat`、拒绝符号链接段、拒绝越界）；
- **相对且含 `..` 段** → 允许越出 cwd，但仍逐段 `lstat`、仍拒绝符号链接段、仍要求末端是目录；退到盘根就停（`path.resolve` 的语义），不再上退。

**保留**符号链接这一条（不跟随目录链接段）：包含判据一旦按用户输入放开，「挡住链接到工作目录之外」这条理由消失，剩下的收益只是「列出链接目标」，而 M1/M2/M3 已经给了三条显式出路，不值得为它引入跟随语义（跟随会把列举引到网络位置或链接环上）。点开头条目与 `excludedDirectories` 照旧跳过，与服务器同判据 —— 因此 `node_modules` 里的东西不会出现在列表里，但**要引用具体路径仍然可以**：把完整路径打全，`mentionResolves` 判「能引用」、列表不弹，正文照旧是一条合法引用。

### 候选合成、排序与上限

越界这一侧由扩展自己出清单（服务器恒空），规则：

- 条目路径 = 查询里那个目录前缀（归一成正斜杠）+ 条目名；尾斜杠由界面 `formatFileMention` 决定，宿主不写（与 `missingDirectoryEntries` 一致）。
- **目录列举**（筛选词为空）：目录在前、再按 path 的原始 code-unit 比较 —— 与服务器空查询时的退化顺序同一条。
- **筛选词查询**（`@D:/dev/other/no`）：本地列目录后按官方 `scoreCandidate` 的**档位顺序近似**筛选：完全相等 > 前缀 > 名字包含 > 路径包含 > 子序列；同档内目录优先、再 code-unit。与官方的差别是子序列档内没有 gap 分数（次序可能不同）且没有 `query === ''` 的短路。**这只作用于越界侧**：服务器对这些查询从不返回任何行，所以不存在「两段规则不同的清单」。
- 上限沿用 `MAX_COMPLETED_ENTRIES`（我们自己补的那一段）与界面 `CANDIDATE_LIST_LIMIT`。
- 任何失败（不存在 / 不可读 / 权限 / 断链）一律静默回退空表：弹层照旧显示「没有匹配的文件」与可用的 `..` 行，不抛错、不把整份列表置空。

### 与抑制门、键盘的交互

- 越界的**文件**路径写全 → `mentionResolves` 判「能引用」→ 整块抑制、列表不弹（回车是发送）；要浏览目录必须带尾分隔符。与工作区内同源，不因越界而例外。
- 键盘继续只认 `popoverOpen`（见「键盘只在弹层画出来时接管」）：抑制门按住时回车归发送、↑↓ 归光标、ESC 归归属链。
- 「上一层」行**只有 pick 有动作**（Enter / 点行主体 = 回上一层）；`drill`（Tab）落在它身上**什么都不做**——它不是可下钻的目录，`hasDrillableFolder` 用的是同一条判据（不然 Tab 也回上一层，与「Tab = 进入目录」的提示自相矛盾）。
- 「上一层」行有两个来源、同一个形状：宿主下发的（裸 `@` 那一层，`items[0]`）与界面自己合成的（`mentionParent` 认出的子目录层）。宿主已经给出时界面原样保留它在首位、**不再合成第二条**；宿主那几条的顺序与位置一个不动。
- **候选行只属于当前查询**：`fileRefs.query` 与当前触发词对不上（这一层的帧还没回来，或回来的是上一次查询的）时，文件 / 对话候选按空算，只有按**当前**查询合成的「上一层」行照常画。浏览入口不等待判定、当场画弹层，拿旧帧去画就会让上一层的宿主「上一层」行与文件行占住首行，快按 Enter 会选到**上一层**的目标（例如从裸 `@` 切到 `@D:/dev/other/`：旧根那一层的 parent 不许占新层的首行）。`cwd` 是会话属性、不随查询变，照旧用当前帧里的那个算深度。
- 会话候选（对话引用）照旧只在工作区根那一层列，越界目录里不列。

### 有意差异与不可得能力

- **有意差异**：官方 `@` 发现以工作目录为根，本扩展在信任门通过时把发现范围扩到本机文件系统。差异登记在本节与 `fileRefListing.ts` 的文件头；**不**登记到[版本兼容](<dsh-compat.md>)——那里管的是随 DSH 版本变动的契约面。
- **不做**：不新增 RPC、不改 `@` 书写形态、不改变有效引用抑制的交互语义、不向上游提交 provider 改动。文件路径抑制仅增加同源信任门。要官方客户端也能列工作区外，只能改上游 provider，本扩展不依赖它。
- **不可得**：门关时（远端 / WSL / 拿不到 cwd 证据）越界**发现**不可得；此时唯一可用的形态是用户手打完整绝对路径。

### 补充决策

- **文件路径抑制复用信任门**：只有门通过才采用本机存在性证据；门关闭时不抑制文件候选、不阻止手写引用或发送。会话引用仍按会话账本判断。
- **显式网络路径与有界等待**：门通过后支持用户输入的 UNC 与映射盘路径，不扫描网络邻居、不探测未输入的共享。本次本地文件系统查询总等待上限为 **1500ms**，覆盖信任门存在性检查、路径检查、抑制判定与目录读取，不为每一步重新计时。超时保留已有服务端结果，不追加本地候选；旧查询失效后丢弃迟到结果。停止等待不等于底层文件系统操作已取消，须限制未完成操作，避免连续输入累积请求。
- **裸 `@` 不列本机盘符**：仍表示工作区根，只增加符合条件的「上一层」。其它盘由显式 `@D:` 或 `@D:/` 进入，不自动枚举盘符。
- **不增加「工作区外」标签**：候选保留绝对路径或 `../` 前缀，悬停可查看完整绝对路径；「上一层」行也显示实际目标的完整路径。长路径的省略不得使目标无法确认，新增界面文案须中英双语。
- **本地筛选采用五档近似**：完全相等 > 名字前缀 > 名字包含 > 路径包含 > 子序列；同档内目录优先、再按原始 code-unit，不复刻子序列 gap 分数。仅作用于工作区外候选，不改变服务端结果。

## 文件先发、会话候选后到

文件候选调用 `fileReferences/list`，会话候选调用 `sessionReferenceResolver/candidates`。后者须扫描项目与会话日志头，显著慢于目录读取；既有 339 条会话样本中，目录约 0.1ms、会话检索超过 130ms。该观察解释分帧选择，不是当前性能保证。

- 两个 RPC 并行发起，`files/list` 先发文件，`files/sessions` 随后独立发会话，两帧都带 query。只串发帧顺序，不串 RPC。
- 界面 `files/list` 只换文件部分，旧会话候选按 stale-while-revalidate 暂留；`files/sessions.query` 与当前查询不符就整帧丢弃。
- `controller.menuQueries` 每次查询作废上一句柄，兼作取消入口与当前批次判据；窗口下线时作废并清表。网关将客户端断开传给请求 signal，服务端扫描可逐步中止，因此取消不只是丢弃结果。
- `composerCompletion.tsx` 的查询串 effect 独占 `@` 重取；导航与选中不另发查询。`/` 目录只在命令通道打开时取一次，查询串过滤在本地做。

### 关键决策与取舍

- 不用 `Promise.all` 等两源一起返回，避免快速文件候选被慢会话扫描阻塞。
- 取消旧 RPC 与界面 query 拒旧帧两道防线都保留：取消不能保证已经在途的帧不会迟到。
- 会话候选有意只在工作区根目录列，偏离官方按查询串在目录内继续筛历史会话的行为。查询串出现分隔符时，宿主连查都不查；界面 `rankCandidates` 的 `isDirectoryQuery` 同步隐藏该组，不等待往返。
- 根目录暂留旧会话候选，避免列表先塌再长；进入目录后整组不可见。目录查询不发 `files/sessions`，状态可保留上一次根目录结果，返回根目录时先显示旧结果再替换。
- 若恢复官方目录内检索，须同时移除宿主与界面判据；不能只改一侧。
