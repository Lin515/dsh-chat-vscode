# 会话列表、空壳与未读

修改列表可见性、空态恢复、运行状态或未读标记前读本文。服务端目录、子代理身份与切会话的字段一致性见[投影设计](<design-projections.md>)；草稿归属见[发送设计](<design-draft.md>)，后台跨窗口生命周期见[连接设计](<design-supervisor.md>)。

## 会话列表与空壳

- title 从列表与投影两路读取；sessionListMetadata 不直接消费，列表已提供折算后的 blank。
- 空态是一条真实空壳，有则复用、无则创建。复用须结合客户端 `engagedSessions`，不能只信滞后的列表 blank，否则首条消息会落进旧会话。
- **空壳照常进历史列表**：它是一条普通可管理行，只多一位 `occupied`——被会话窗口拿着（绑着或正在落壳）的空壳在界面上锁住（`sessionSelection.sessionLocked`：不可勾选、不给归档 / 删除按钮），没被拿着的照常可归档 / 删除。`occupied` 由宿主按当下这一刻现算（不落进 `this.sessions`），占用变化会重发列表帧。`@` 提及的对话候选**仍然**滤掉空壳（`visibleSessionCandidates`）：引一条还没有内容的新建壳没有意义。
- **删掉一条空壳**只走本地那一条路（服务端没有删除端点，见下）：`deleteSession` 在 `isSafeSessionId`、运行中、当前窗口正在看之外，**再拒一次被任何窗口拿着（含预留中）的空壳**——界面上那颗垃圾桶本就不给（`occupied`），宿主这条是第二道。
- **接回一条已有空壳要过服务端**（`session/create` 指名 `sessionId`，`adoptBlankShell`）：服务端只为在册会话激活 Agent。客户端过去只把会话绑上、激活全靠跟随流的后台提升，而那条提升在「日志里记着的预设已经不存在」时必然失败（重建会话要按 `agentPreset` 投影组装）——`agentPresets/select` 按 Agent 查找（只认活着的），于是预设切换与这条会话上的一切一起废掉，用户看到的是「点预设胶囊弹切换失败、消息也发不出去」。认领时把日志里记着的预设照原样报一次（还在就什么都不改，保住「复用不动它的预设」），服务端回 `agent-preset/not-found` / `agent-preset/invalid` / `agent-preset/conflict` 时不带预设再认领一次，由它按部署默认组装（官方 `ui-workspace` 的 `createInWorkspace` / `restoreBlank` 同款）。同步换绑（`switchToBlankSync`）与打开 / 恢复一条空壳（`openSession`）两条路把这一趟放在推完快照之后补发。
- **当前停在一条空壳上时再点「+」是完全 no-op**（用户 2026-10-17 口径）：什么都不做——不清输入框 / 附件草稿 / 待发与失败回显 / 空态页那几项待建选择，不改模型 / 思考强度 / 权限 / 预设 / 工作目录，不换绑定、不认领、不连后台、不发任何 RPC、不另建也不删，只记一行开发者日志（`newSession` 的入口判据）。判据只有一条：`isBlankShell`（服务端 `blank` 位 + 本地 `engagedSessions` 都没说它已经说过话），**不做任何加料**——既不排除「正在生成」（生成中的会话会被 `markSessionEngaged` 翻掉 blank 位），也不读日志脏不脏：改过的标题、计划模式、目标 / 待办、自动化任务都与这一下无关。判据与返回都在占动作代号与任何 await **之前**，所以这一下不动窗口的动作代号，也不作废别人在飞的动作。
- **其它情况照旧落一条空壳**：窗口停在内容会话上或还没有壳时，先同步退回空态并推那一帧（`detachView` + 整份快照），再 `await ensureSession` 去接回或新建；手里已经有一条没被别人拿着的现成空壳时更快——同步换绑（`switchToBlankSync`，0 往返），指名认领随后在后台补发（见上一条与下一条）。
- **一次点击 / 打开 / 恢复都是一次动作，跨 await 要重验身份**（`viewActions` 代号 + 绑定，`viewActionIsCurrent`）：`openSession` / `restoreViewSession` 在 `ensureConnected`、拉列表之后、真正绑定之前复查——这期间用户点开历史里的一条、关掉窗口、或再点一次「+」，都让这一次收手，绝不覆盖他刚选的会话（只看 `viewSessions` 不够：切走再回来是同一个值）。代号是只增不减的全局序号，比较它同时覆盖换绑、关窗与 ABA；关窗时条目一并删掉（不留增长，同 id 重建也拿不到旧号）。点「+」自己占一号，正是让别的路径回来时发现意图已经换人。
- **空壳按会话窗口独占，不跨窗口共享**：`blankOccupants`（会话 → 窗口，已绑事实）与 `blankReservations`（会话 → 窗口 + 代号，正在落壳的预留）两张**运行期**表——不落盘，扩展重启后任何会话打开之前都是空的。别的窗口拿着（占用或预留）的壳不进 `reusableBlank`，所以第二个窗口进空态时另建一条。**判据与预留在同一个同步步骤**（`reserveReusableBlank`）：从判据到写绑定跨了一串 await，只判不占会让两个并发窗口挑中同一条。**新建 / 认领拿到 id 的那一刻也要当场占住它**（`reserveBlankFor`，`ensureSession` 按**代号**释放）：不占的话，落壳链里那次 `refreshSessions` 的往返期间另一个窗口就能从列表里看到这条新壳、预留并绑走它，等它回来再一绑就是两个窗口共享同一条壳、占用表还被覆盖成后来者。**绑定临界区再确认一次 `blankHolder`**：不是自己就让位（另铸一条 / 不绑），绝不覆盖别人的占用。释放只认自己那一号（代号守卫：迟到的收尾删不掉后来者的预留；同一份预留在换 key 之后仍按代号放得掉），释放点覆盖换绑、退回空态、窗口下线、空壳被说过话 / 被删、连接收线；条目变化会重发列表帧。**内容会话的共享不受影响**：两个窗口看同一条已开始的对话照旧容许。
- **打开 / 恢复一条被别的窗口拿着的空壳**（`openSession`，`restoreViewSession` 也走它）→ 不共享，改落一条本窗口自己的新壳；被拿着的那条不动。判据只看 `blankHolder`（占用 + 预留），**不要求列表里那一行说 `blank`**：列表可能还没拉到那条行（`isBlankShell` 因此为假），而两张表已经证明它是别人正在用的空壳——缺行正是预留要覆盖的那一档。
- 后台补壳必须让位恢复：入口跳过 `hasRestorePending`，写绑定前再查窗口是否已被恢复或手动打开路径绑定，**并查这个窗口在落壳期间有没有被关掉**（关掉了就不写绑定、也不建域——`ensureScope` 放在这些检查之后，否则那两条长活流会留给一个没人看的域）。
- 无 cwd 不建壳。没有 VS Code 文件夹时可反复选择目录；换目录是换到该目录的空壳，不修改已聊会话的 cwd（换回原目录时，那条壳还空着且没人占着才会被接回来）。
- 打开文件夹时按工作区登记与 cwd 过滤（含「任何已打开域的 cwd」兜底）；未打开文件夹时全局候选保持完整，**发帧前**再按窗口收窄：窗口有目录就只留该目录（注册分组无关），还停在空态（没选目录）就只列**未分组**的会话——「未分组」按服务端注册表判（没有任何工作区记过它），别的窗口打开过某个目录不构成这个窗口该看见它的理由。按服务端 updatedAt 降序，不另猜 lastPromptAt。
- 会话的 cwd 与「日志里记着的 agent 预设」两张账本都从 `session/list` 的原始行整份重建（`sessionCwds` / `sessionPresets`），换连接时清空。预设取投影值（服务端重建会话读的就是它，header 只是创建事实），且只用来「照原样再报一次」，权威判定留给服务端。

## 生成完毕未读

未读是扩展自己的客户端状态，官方 `SessionSummary` 没有这个概念。只有离开时会话正在生成，且本宿主内没有任何会话视图仍打开它，才留下离开标记；该实例生成完成时，再确认没有会话视图正在查看它，才结算为未读。用户回来查看后清除未读。

离开标记在 controller 的 `leftGeneratingSessionIds`（内存），已结算未读在 `unreadSessionIds`（持久化），结算入口为 `settleRunningChange`。视图打开情况只覆盖本扩展宿主内的窗口，不包括其他独立 VS Code 扩展宿主或浏览器。

### 关键决策与取舍

- 不按“后台从运行变为空闲”直接点亮未读：否则别处启动、本窗口从未打开的会话也会被点亮。离开标记将未读与用户确实离开过的生成实例关联。
- 每会话一个 `globalState` 键 `unread:<会话 id>`，清除即删键，窗口只写自己刚改过的项。整份数组覆写会把其他窗口已经清掉的旧标记写回来；逐项键消除这条覆写通道，但不提供跨窗口实时同步。
- 启动时作废旧口径的整份数组：旧规则产生的标记无法按现规则解释，宁可少亮一次也不保留错误未读。删除 / 归档会话同时清除标记，避免已无列表入口的旗标永不清理。

## 运行状态对账

`api-session/status` 与 durable `turn/end` 是两条流，收尾先后无保证。列表行与会话域须同步对账：

1. `SessionAdapter` 的 durable running 回调同时交给 `setSessionRowRunning`；只改域而不改列表，会让早已结束的会话在离开时被误判为仍生成。
2. 本地有开放轮次时，`acceptSessionStatus` 拒收服务端的 false，防乱序旧值撤掉停止按钮或让 `waitUntilIdle` 提早结束。等审批 / 等提问时没有活跃 attempt 也可能仍属开放轮次。
3. 被拒收值存入 `pendingStatuses`，本地开放轮次判据变化（如域回收、适配器消失）后复查。拒收不等于忘记；durable running 结论到达时直接作废旧记账，不能留待未来重放。

有意保留的例外：本地轮次仍开放时，视图继续显示生成中，离开照样留标记。修复的是 durable 收尾后列表残留，不是取消这条例外。

## 历史列表的多选形态

用户 2026-10-15 口径：抽屉顶部（归档切换按钮**左边**，与它同一套切换制）加一颗多选开关，点开才长出复选框与批量工具条、再点一次退出；形态下可「全选」，对选中项归档或删除（删除要二次确认）；切到归档列表复用同一套逻辑，只是归档那颗变成**恢复**，删除两边一致。判据集中在 `webview/sessionSelection.ts`（纯函数，回归 `sessionSelection.test.ts`），组件只做接线。

- **平时不是多选**：复选框与批量工具条挂在同一个形态开关下（用户口径「不是要常驻多选框」），抽屉平时就是一张干净的历史列表；进出形态都清掉选择集与确认态，进来时不带上次的残留。
- **形态下整行是选择目标**：点行 = 勾选 / 取消勾选，**不打开会话**（进来是做批量操作的，误触打开一条会把刚挑的一半选择带走）；复选框是它的状态指示，被勾中的行整行淡染，不必去认那颗小方框。复选框自绘，不用原生外观——系统那套白底蓝勾与深色主题下的细描边不是一种语言，尺寸也不跟 `--dp`。勾本身是「铺满输入框内框的一层 + 六边形 `clip-path`」：被 `transform` 的小盒子按亚像素栅格化、方框却吸附在整数设备像素上，两者叠加会让勾相对方框偏半个像素且偏向随侧栏宽度摇摆（用户报的「偏左」）；铺满内框后勾跟着方框自己的像素网格走，那条对角差（墨迹外接框比盒子中心低 `min(宽, 高) / (2√2)`）直接写进顶点坐标里。顺带绕开了 Chromium 把 `border-width` 向下取整到整数设备像素的问题。
- **可选判据与行内的归档 / 恢复 / 删除同源**（`sessionLocked`）：运行中的会话服务端还在往里写、当前会话删完无处可看、**被别的窗口拿着的空壳**（`occupied`，空壳不跨窗口共享），宿主三条都拒（controller 的 `deleteSession`）。这些行勾不上、行也点不动，复选框只留一个淡描边空框（否则一次批量点击换来几条拒绝提示）。
- **选择集跟随当前列表**：搜索改变可见行、切视图换一份列表、归档 / 恢复 / 删除后行消失，看不见的选中项都要退掉（`pruneSelection`）——留着就是看不见却会被批量操作命中的幽灵选择。切视图保留形态本身（用户切过去多半接着挑），只清选择。
- **「全选」是翻转**：还没全选就选中全部，已经全选就取消全部；作用范围是**当前可见且可选**的那些行（搜索是筛选、不是另一次选择）。
- **删除两段式**：与行内垃圾桶同一条口径（`DELETE_ARM_MS` 武装 3 秒，确认文案带影响条数）；同一时刻只留一个待确认目标，改选择或切视图即作废确认。
- **恢复归档**走 `workspace/unarchiveSession`（与归档同一个 `WorkspaceArchiveValue`）：本地先把 id 从 `archivedSessionIds` 退掉让列表立刻回到普通视图，权威值仍由 `workspace/follow` 的 `archived` 增量确认——与归档是同一条链路，不另设一套。
- 批量操作对选中项**逐条**发既有的单条消息（`archiveSession` / `unarchiveSession` / `deleteSession`），不新开批量端点：安全会话 id、运行中、当前查看这三道校验都在单条路径上，绕过它等于把它们复制一份。

## 验证与未覆盖边界

回归入口：blankSessionReuse、blankRestoreRace、blankPresetAdopt、blankSessionNoop、emptyComposer、workspaceDirRepick、sessionSelection、composerSessionDraft、commandNode、unreadMarker。覆盖空壳参与状态、首条消息归属与本地 blank 位折算、恢复让位、认领与预设兜底、**停在空壳上点「+」完全 no-op**（改过模型 / 思考强度 / 权限 / 预设、留着草稿附件与失败回显、有标题 / 计划 / 目标 / 自动化任务、断连、模型目录不可用各档都不发一帧也不发一笔 RPC，反复点仍是同一条壳）、无壳 / 内容会话照旧落壳（接回没人占用的现成壳要一次指名认领，否则真新建）、**空壳按窗口独占**（两个窗口并发各自落壳、打开别人拿着的壳改落自己的、占用账本不被覆盖）、预留代号与关窗收手、历史列表的占用锁、运行状态对账、逐项未读持久化、删除清理与多选判据，不替代全部跨宿主时序验证。

- 不跨独立 VS Code 窗口登记“哪个窗口打开哪条会话”；要支持它，须在 supervisor 共享通道增加登记协议。
- 不与浏览器 dsh web 同步未读：服务端没有这项客户端状态。
- 上述未实现能力是明确范围边界，不应凭现有回归宣称全局未读一致。
