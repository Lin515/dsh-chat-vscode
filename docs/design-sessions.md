# 会话列表、空壳与未读

修改列表可见性、空态恢复、运行状态或未读标记前读本文。服务端目录、子代理身份与切会话的字段一致性见[投影设计](<design-projections.md>)；草稿归属见[发送设计](<design-draft.md>)，后台跨窗口生命周期见[连接设计](<design-supervisor.md>)。

## 会话列表与空壳

- title 从列表与投影两路读取；sessionListMetadata 不直接消费，列表已提供折算后的 blank。
- 空态是一条真实空壳，有则复用、无则创建。复用须结合客户端 `engagedSessions`，不能只信滞后的列表 blank，否则首条消息会落进旧会话。
- 后台补壳必须让位恢复：入口跳过 `hasRestorePending`，写绑定前再查窗口是否已被恢复或手动打开路径绑定。
- 无 cwd 不建壳。没有 VS Code 文件夹时可反复选择目录；换目录是换到该目录的空壳，不修改已聊会话的 cwd。
- 列表过滤全部 blank 与 subagent 行；允许多窗口共用空壳。这是与单视图官方 UI 不同的产品取舍。
- 打开文件夹时按工作区登记与 cwd 过滤；未打开文件夹时，发帧前按各窗口当前会话 cwd 收窄。按服务端 updatedAt 降序，不另猜 lastPromptAt。

## 生成完毕未读

未读是扩展自己的客户端状态，官方 `SessionSummary` 没有这个概念。只有离开时会话正在生成，且本宿主内没有任何会话视图仍打开它，才留下离开标记；该实例生成完成时，再确认没有会话视图正在查看它，才结算为未读。用户回来查看后清除未读。

离开标记在 controller 的 `leftGeneratingSessionIds`（内存），已结算未读在 `unreadSessionIds`（持久化），结算入口为 `settleRunningChange`。视图打开情况只覆盖本扩展宿主内的窗口，不包括其他独立 VS Code 扩展宿主或浏览器。

### 关键决策与取舍

- 不按“后台从运行变为空闲”直接点亮未读：否则别处启动、本窗口从未打开的会话也会被点亮。离开标记将未读与用户确实离开过的生成实例关联。
- 每会话一个 `globalState` 键 `unread:<会话 id>`，清除即删键，窗口只写自己刚改过的项。整份数组覆写会把其他窗口已经清掉的旧标记写回来；逐项键消除这条覆写通道，但不提供跨窗口实时同步。
- 启动时作废旧口径的整份数组：旧规则产生的标记无法按现规则解释，宁可少亮一次也不保留错误未读。删除 / 归档会话同时清除标记，避免已无列表入口的旗标永不清理。

## 运行状态对账

`api-session/status` 与 durable `turn/end` 是两条流，收尾先后无保证。列表行与会话域须同步对账：

1. `SessionAdapter` 的 durable running 回调同时交给 `setSessionRowRunning`；只改域而不改列表，会让早已结束的会话在离开时被误判为仍生成。
2. 本地有开放轮次时，`acceptSessionStatus` 拒收服务端的 false，防乱序旧值撤掉停止按钮或让 `waitUntilIdle` 提早结束。等审批 / 等提问时没有活跃 attempt 也可能仍属开放轮次。
3. 被拒收值存入 `pendingStatuses`，本地开放轮次判据变化（如域回收、适配器消失）后复查。拒收不等于忘记；durable running 结论到达时直接作废旧记账，不能留待未来重放。

有意保留的例外：本地轮次仍开放时，视图继续显示生成中，离开照样留标记。修复的是 durable 收尾后列表残留，不是取消这条例外。

## 历史列表的多选形态

用户 2026-10-15 口径：抽屉顶部（归档切换按钮**左边**，与它同一套切换制）加一颗多选开关，点开才长出复选框与批量工具条、再点一次退出；形态下可「全选」，对选中项归档或删除（删除要二次确认）；切到归档列表复用同一套逻辑，只是归档那颗变成**恢复**，删除两边一致。判据集中在 `webview/sessionSelection.ts`（纯函数，回归 `sessionSelection.test.ts`），组件只做接线。

- **平时不是多选**：复选框与批量工具条挂在同一个形态开关下（用户口径「不是要常驻多选框」），抽屉平时就是一张干净的历史列表；进出形态都清掉选择集与确认态，进来时不带上次的残留。
- **形态下整行是选择目标**：点行 = 勾选 / 取消勾选，**不打开会话**（进来是做批量操作的，误触打开一条会把刚挑的一半选择带走）；复选框是它的状态指示，被勾中的行整行淡染，不必去认那颗小方框。复选框自绘，不用原生外观——系统那套白底蓝勾与深色主题下的细描边不是一种语言，尺寸也不跟 `--dp`。勾本身是「铺满输入框内框的一层 + 六边形 `clip-path`」：被 `transform` 的小盒子按亚像素栅格化、方框却吸附在整数设备像素上，两者叠加会让勾相对方框偏半个像素且偏向随侧栏宽度摇摆（用户报的「偏左」）；铺满内框后勾跟着方框自己的像素网格走，那条对角差（墨迹外接框比盒子中心低 `min(宽, 高) / (2√2)`）直接写进顶点坐标里。顺带绕开了 Chromium 把 `border-width` 向下取整到整数设备像素的问题。
- **可选判据与行内的归档 / 恢复 / 删除同源**（`sessionLocked`）：运行中的会话服务端还在往里写、当前会话删完无处可看，宿主两条都拒（controller 的 `deleteSession`）。这两类勾不上、行也点不动，复选框只留一个淡描边空框（否则一次批量点击换来几条拒绝提示）。
- **选择集跟随当前列表**：搜索改变可见行、切视图换一份列表、归档 / 恢复 / 删除后行消失，看不见的选中项都要退掉（`pruneSelection`）——留着就是看不见却会被批量操作命中的幽灵选择。切视图保留形态本身（用户切过去多半接着挑），只清选择。
- **「全选」是翻转**：还没全选就选中全部，已经全选就取消全部；作用范围是**当前可见且可选**的那些行（搜索是筛选、不是另一次选择）。
- **删除两段式**：与行内垃圾桶同一条口径（`DELETE_ARM_MS` 武装 3 秒，确认文案带影响条数）；同一时刻只留一个待确认目标，改选择或切视图即作废确认。
- **恢复归档**走 `workspace/unarchiveSession`（与归档同一个 `WorkspaceArchiveValue`）：本地先把 id 从 `archivedSessionIds` 退掉让列表立刻回到普通视图，权威值仍由 `workspace/follow` 的 `archived` 增量确认——与归档是同一条链路，不另设一套。
- 批量操作对选中项**逐条**发既有的单条消息（`archiveSession` / `unarchiveSession` / `deleteSession`），不新开批量端点：安全会话 id、运行中、当前查看这三道校验都在单条路径上，绕过它等于把它们复制一份。

## 验证与未覆盖边界

回归入口：blankSessionReuse、blankRestoreRace、workspaceDirRepick、unreadMarker、sessionSelection。覆盖空壳参与状态、恢复让位、运行状态对账、逐项未读持久化、删除清理与多选判据，不替代全部跨宿主时序验证。

- 不跨独立 VS Code 窗口登记“哪个窗口打开哪条会话”；要支持它，须在 supervisor 共享通道增加登记协议。
- 不与浏览器 dsh web 同步未读：服务端没有这项客户端状态。
- 上述未实现能力是明确范围边界，不应凭现有回归宣称全局未读一致。
