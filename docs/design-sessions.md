# 会话列表、空壳与未读

修改列表可见性、空态恢复、运行状态或未读标记前读本文。服务端目录、子代理身份与切会话的字段一致性见[投影设计](<design-projections.md>)；草稿归属见[发送设计](<design-draft.md>)，后台跨窗口生命周期见[连接设计](<design-supervisor.md>)。

## 会话列表与空壳

- title 从列表与投影两路读取；sessionListMetadata 不直接消费，列表已提供折算后的 blank。
- 空态是一条真实空壳，有则复用、无则创建。复用须结合客户端 `engagedSessions`，不能只信滞后的列表 blank，否则首条消息会落进旧会话。
- **空壳照常进历史列表**：它是一条普通可管理行，只多一位 `occupied`——正被本宿主某个会话窗口停着的空壳在界面上锁住（`sessionSelection.sessionLocked`：不可勾选、不给归档 / 删除按钮），没人停着时照常可归档 / 删除。`occupied` 由宿主按当下绑定和 `isBlankShell` 现算（不落进 `this.sessions`）；首条消息一旦让本地记为已开始，即使列表未刷新也不再按空壳上锁。绑定变化会重发列表帧。**它表示「在用」，不是独占**：空壳由窗口共享（见下）。`@` 提及的对话候选**仍然**滤掉空壳（`visibleSessionCandidates`）：引一条还没有内容的新建壳没有意义。
- **删掉一条空壳**只走本地那一条路（服务端没有删除端点，见下）：`deleteSession` 在 `isSafeSessionId`、运行中、当前窗口正在看之外不另设空壳专用闸——空壳与内容会话同一条判据（有窗口看着就不许删）。界面上那颗垃圾桶本就不给（`occupied`）。
- **接回一条已有空壳要过服务端**（`session/create` 指名 `sessionId`，`adoptBlankShell`）：服务端只为在册会话激活 Agent。客户端过去只把会话绑上、激活全靠跟随流的后台提升，而那条提升在「日志里记着的预设已经不存在」时必然失败（重建会话要按 `agentPreset` 投影组装）——`agentPresets/select` 按 Agent 查找（只认活着的），于是预设切换与这条会话上的一切一起废掉，用户看到的是「点预设胶囊弹切换失败、消息也发不出去」。认领时把日志里记着的预设照原样报一次（还在就什么都不改，保住「复用不动它的预设」），服务端回 `agent-preset/not-found` / `agent-preset/invalid` / `agent-preset/conflict` 时不带预设再认领一次，由它按部署默认组装（官方 `ui-workspace` 的 `createInWorkspace` / `restoreBlank` 同款）。同步换绑（`switchToBlankSync`）与打开 / 恢复一条空壳（`openSession`）两条路把这一趟放在推完快照之后补发。
- **当前停在一条空壳上时再点「+」是完全 no-op**（用户 2026-10-17 口径）：什么都不做——不清输入框 / 附件草稿 / 待发与失败回显 / 空态页那几项待建选择，不改模型 / 思考强度 / 权限 / 预设 / 工作目录，不换绑定、不认领、不连后台、不发任何 RPC、不另建也不删，只记一行开发者日志（`newSession` 的入口判据）。判据只有一条：`isBlankShell`（服务端 `blank` 位 + 本地 `engagedSessions` 都没说它已经说过话），**不做任何加料**——既不排除「正在生成」（生成中的会话会被 `markSessionEngaged` 翻掉 blank 位），也不读日志脏不脏：改过的标题、计划模式、目标 / 待办、自动化任务都与这一下无关。判据与返回都在占动作代号与任何 await **之前**，所以这一下不动窗口的动作代号，也不作废别人在飞的动作。
- **其它情况照旧落一条空壳**：窗口停在内容会话上或还没有壳时，先同步退回空态并推那一帧（`detachView` + 整份快照），再 `await ensureSession` 去接回或新建；手里已经有一条现成空壳时更快——同步换绑（`switchToBlankSync`，0 往返），指名认领随后在后台补发（见上一条与下一条）。
- **一次点击 / 打开 / 恢复都是一次动作，跨 await 要重验身份**（`viewActions` 代号 + 绑定，`viewActionIsCurrent`）：`openSession` / `restoreViewSession` 在 `ensureConnected`、拉列表之后、真正绑定之前复查——这期间用户点开历史里的一条、关掉窗口、或再点一次「+」，都让这一次收手，绝不覆盖他刚选的会话（只看 `viewSessions` 不够：切走再回来是同一个值）。代号是只增不减的全局序号，比较它同时覆盖换绑、关窗与 ABA；关窗时条目一并删掉（不留增长，同 id 重建也拿不到旧号）。点「+」自己占一号，正是让别的路径回来时发现意图已经换人。
- **空壳由窗口共享，不按标签各占一条**（用户 2026-11-02 口径，取代 2026-10-17 的按窗口独占）：一个工作区只有一条空壳，谁进空态都接它（官方 `ui-workspace` 的字面行为）。打开 / 恢复一条别的窗口正停着的空壳照常绑上去——与两个窗口看同一条已开始的对话是同一件事。**并发进入空态只落一条壳**：`blankEnsures`（归一后的目录 → 队尾 promise）把「扫描 → 认领 / 新建 → 刷新列表」串行化（`withBlankGate`），后到的窗口在闸内重扫列表、接到前一条上；不串行的话，几个窗口同时进空态会各建一条，又回到「开几个标签就有几条空壳」。运行期状态、不落盘，没有预留 / 占用账本。
- **后台补壳必须让位恢复**：入口跳过 `hasRestorePending`，写绑定前再查窗口是否已被恢复或手动打开路径绑定，**并查这个窗口在落壳期间有没有被关掉**（关掉了就不写绑定、也不建域——`ensureScope` 放在这些检查之后，否则那两条长活流会留给一个没人看的域）。
- 无 cwd 不建壳。没有 VS Code 文件夹时，空壳的复用键就是**用户在新会话页上选定的那个目录**（`newSessionCwd`，宿主级一个值；已绑定窗口显示的是自己那条会话的 cwd）：还没有目录时窗口停在「未选择工作区」、不建壳，第一次发消息才弹目录选择器；选定之后，同一目录里已有的空壳会被接回来，读不到目录证据就不猜（`reusableBlank` 按 `normalizePath` 比较）。换目录是换到该目录的空壳，不修改已聊会话的 cwd（换回原目录时，那条壳还空着就会被接回来）；并发进入空态仍由 `blankEnsures` 的闸保证一个目录只落一条。
- 旧列表帧（`sessions` / `archivedSessions`，jobs 等消费者）仍按原口径：打开文件夹时按该窗口选中的根、工作区登记与 cwd 过滤（含「任何已打开域的 cwd」兜底）；未打开文件夹时全局候选保持完整，**发帧前**再按窗口收窄：窗口有目录就只留该目录（注册分组无关），还停在空态（没选目录）就只列**未分组**的会话——「未分组」按服务端注册表判（没有任何工作区记过它），别的窗口打开过某个目录不构成这个窗口该看见它的理由。历史抽屉另走「历史抽屉的只读范围」。按服务端 updatedAt 降序，不另猜 lastPromptAt。
- 会话的 cwd 与「日志里记着的 agent 预设」两张账本都从 `session/list` 的原始行整份重建（`sessionCwds` / `sessionPresets`），换连接时清空。预设取投影值（服务端重建会话读的就是它，header 只是创建事实），且只用来「照原样再报一次」，权威判定留给服务端。

## 编辑区标签与宿主失联

VS Code 从单文件夹转成多根工作区时可能重启扩展宿主，但保留原编辑区 webview、又未调用面板序列化器。此时本地 UI 还能切页，却收不到任何宿主回复。同样的提示不以 DSH 服务是否已连接为判据：`watchHostConnection` 只在 webview 可见时探测自己的宿主消息通道，`ChatViewProvider` 在进入控制器之前直接向原窗口回执，不改变活动窗口、会话或连接。可见时每两秒检查一次，回到页面或点击标题栏中需要宿主处理的按钮时立即检查；已有探测在途就复用，不等待回执或重发原操作。满三秒既没收到对应回执也没收到其他宿主帧，才提示失联；恢复通信就撤掉提示。

不自动重载或关闭标签，用户仍能复制未发送的草稿。提示中的固定命令链接只允许调用 VS Code 的「重载窗口」，不依赖失联的扩展宿主；重载后走原有面板序列化恢复。轨迹已加载时仍可查看已有内容；尚未加载时只显示全局失联提示，不继续显示等待宿主的加载态；通信恢复后回到正常加载。回归见 [viewHostConnection.test.ts](<../scripts/viewHostConnection.test.ts>)；单文件夹转多根并保留原标签的场景须在真实 VS Code 中验证。

## 工作目录：每窗口的根

新会话落在哪个目录是**窗口级**选择，不是宿主级：`ChatController` 按 `viewId` 记一份根（`viewRootChoices`），另一个窗口换根不会覆盖本窗口。`workspaceState` 只记**默认偏好**（`dshChat.activeRoot`）——下次新开窗口从哪个根开始；不记各窗口当前绑定状态。默认偏好指向的根被移出工作区时回到第一个根，不沿用旧路径。

- **打开文件夹**：`WorkspaceView` 给出 `path`（本窗当前根）、`locked: true`、`roots`（全部根，`DirectoryOption { path, name }`）与 `canPickOther`。`switchRoot` 只接受当前工作区里的根；`pickOtherRoot` 可选任意目录。空会话 / 还没落壳的窗口才能换（`canChangeRoot`）；已经说过话的会话不迁移，会话 header 的 cwd 是创建事实。
- **工作区外目录**：只在当前扩展宿主里有效，**不注册**服务端工作区，按 cwd 建会话、落在未分组；重载窗口 / 工作区文件夹变化后回到项目根。`pickWorkspace` 和 `pickOtherRoot` 的系统选择结果都经本机身份门（与 `@` 工作区外发现共用 `LocalAccessGate`）；验证后还须重查窗口和动作是否有效，验证失败或动作失效不改变原目录。这个检查不证明远端服务能访问本机目录；远端 VS Code 窗口禁用这两条入口。
- **注册缓存**（`workspaceRegistrations`）按**连接世代 + 目录键 + 是否注册**分键；`workspace/follow` 的快照里有该目录就直接复用，没有才 `workspace/create`。换连接 / 移除根不会沿用旧 `workspaceId`。路径键在 Windows 形态下不区分大小写，POSIX 形态保留大小写与反斜杠（`shared/workspacePath` 的 `directoryPathKey`）。
- **竞态**：换根、选目录、发送、打开会话、关窗共用 `viewActions` 代号。只有发送会在入口**同步冻结**目标目录（`captureSessionTarget`）。按下时已有绑定就以该会话为准，不受根偏好影响；等待期间绑定被替换，消息回到输入框。无绑定时只接受冻结目录，或者在当时没有目录的情况下由用户明确选择；等待期间才出现的根或自动补壳不能代替这一选择。换根只是可被后续操作取消的绑定意图，异步落壳回来后、写绑定前都须核对动作代号和窗口当前根。不同目录的在飞请求不合并，也不能把已失效的绑定意图作为可复用结果。`detachStaleBlank` 让不再匹配当前根的空壳在第一次发送 / 落壳前失去资格。

## 历史抽屉的只读范围

历史与「当前工作区的会话列表」是两件事：`ChatState.history` 按窗口下发，旧的顶层 `sessions` / `archivedSessions` 帧仍按原口径服务 jobs 等消费者，不受历史范围影响。

- `HistoryScope` 默认是 `current`：绑定会话的创建目录；未绑定时本窗预选的新目录；都没有时沿用旧「未分组」口径。只有 VS Code 工作区有至少两个显式根时，抽屉才提供范围选择器，可切到「全部工作区根目录」（`roots`）或其中一个根（`directory`）。这两个范围按归一化后的目录键精确匹配显式根，不递归纳入子目录。会话记录与空会话选址都不会增加历史候选；移除根导致所选范围失效时折回 `current`。
- 宿主从**同一份权威 `session/list`** 建完整候选镜像（`historySessions`），不依赖已按当前根收窄的 `this.sessions`；内部复用空壳、恢复、未读、`@` 仍读旧列表。发帧时按范围过滤（`historyRowsForScope`），归档规则与时间顺序沿用 `groupSessionLists`。连接换代时，旧会话行不得混入新快照；同一端点重连时保留仍有效的窗口范围。
- `setHistoryScope` 逐字段校验（`parseHistoryScope`）并核对目录仍然可选；无效 / 迟到的范围整条拒绝。切换范围只推本窗口的 `history` patch，不注册、不落壳、不刷新 RPC，也不改默认口径。
- 首帧（`ready`）与打开 / 恢复会话的整份快照都带 `history` 镜像，界面不必等下一次列表请求。归档 / 恢复 / 空壳占用变化与范围切换走同一条按窗口的发射路径。
- 子代理会话仍不进历史；`@` 对话候选仍用官方 resolver 与既有跨目录检索，不套用历史范围。

## 生成完毕未读

未读是扩展自己的客户端状态，官方 `SessionSummary` 没有这个概念。只有离开时会话正在生成，且本宿主内没有任何会话视图仍打开它，才留下离开标记；该实例生成完成时，再确认没有会话视图正在查看它，才结算为未读。用户回来查看后清除未读。

离开标记在 controller 的 `leftGeneratingSessionIds`（内存），已结算未读在 `unreadSessionIds`（持久化），结算入口为 `settleRunningChange`。视图打开情况只覆盖本扩展宿主内的窗口，不包括其他独立 VS Code 扩展宿主或浏览器。

### 关键决策与取舍

- 不按“后台从运行变为空闲”直接点亮未读：否则别处启动、本窗口从未打开的会话也会被点亮。离开标记将未读与用户确实离开过的生成实例关联。
- 每会话一个 `globalState` 键 `unread:<会话 id>`，清除即删键，窗口只写自己刚改过的项。整份数组覆写会把其他窗口已经清掉的旧标记写回来；逐项键消除这条覆写通道，但不提供跨窗口实时同步。
- 启动时作废旧口径的整份数组：旧规则产生的标记无法按现规则解释，宁可少亮一次也不保留错误未读。删除 / 归档会话同时清除标记，避免已无列表入口的旗标永不清理。

## 运行状态对账

`api-session/status` 与 durable `turn/end` 是两条流，收尾先后无保证。列表行与会话域须同步对账：

1. `SessionAdapter` 的 durable running 回调同时交给 `setSessionRowRunning`；只改域而不改列表，会让早已结束的会话在离开时被误判为仍生成。
2. 本地有开放轮次时，`acceptSessionStatus` 拒收服务端的 false，防乱序旧值撤掉停止按钮或让 `waitUntilIdle` 提早结束。等审批 / 等提问时没有活跃 attempt 也可能仍属开放轮次。
3. 被拒收值存入 `pendingStatuses`，本地开放轮次判据变化（如域回收、适配器消失）后复查。拒收不等于忘记；durable running 结论到达时直接作废旧记账，不能留待未来重放。

有意保留的例外：本地轮次仍开放时，视图继续显示生成中，离开照样留标记。修复的是 durable 收尾后列表残留，不是取消这条例外。

计时用 `turn/start` 的事件时刻（`runStartedAt`，官方 `startTime`），`turn/end` 清掉；认不出起点时不下发，界面只显示「深度求索中」，不用 `Date.now()` 现算。

## 历史列表的多选形态

用户 2026-10-15 口径：抽屉顶部（归档切换按钮**左边**，与它同一套切换制）加一颗多选开关，点开才长出复选框与批量工具条、再点一次退出；形态下可「全选」，对选中项归档或删除（删除要二次确认）；切到归档列表复用同一套逻辑，只是归档那颗变成**恢复**，删除两边一致。判据集中在 `webview/sessionSelection.ts`（纯函数，回归 `sessionSelection.test.ts`），组件只做接线。

- **平时不是多选**：复选框与批量工具条挂在同一个形态开关下（用户口径「不是要常驻多选框」），抽屉平时就是一张干净的历史列表；进出形态都清掉选择集与确认态，进来时不带上次的残留。
- **形态下整行是选择目标**：点行 = 勾选 / 取消勾选，**不打开会话**（进来是做批量操作的，误触打开一条会把刚挑的一半选择带走）；复选框是它的状态指示，被勾中的行整行淡染，不必去认那颗小方框。复选框自绘，不用原生外观——系统那套白底蓝勾与深色主题下的细描边不是一种语言，尺寸也不跟 `--dp`。勾本身是「铺满输入框内框的一层 + 六边形 `clip-path`」：被 `transform` 的小盒子按亚像素栅格化、方框却吸附在整数设备像素上，两者叠加会让勾相对方框偏半个像素且偏向随侧栏宽度摇摆（用户报的「偏左」）；铺满内框后勾跟着方框自己的像素网格走，那条对角差（墨迹外接框比盒子中心低 `min(宽, 高) / (2√2)`）直接写进顶点坐标里。顺带绕开了 Chromium 把 `border-width` 向下取整到整数设备像素的问题。
- **可选判据与行内的归档 / 恢复 / 删除同源**（`sessionLocked`）：运行中的会话服务端还在往里写、当前会话删完无处可看、**正被某个窗口用着的空壳**（`occupied`），宿主都拒（controller 的 `deleteSession` 对前两类与「有窗口看着」这一条）。这些行勾不上、行也点不动，复选框只留一个淡描边空框（否则一次批量点击换来几条拒绝提示）。
- **选择集跟随当前列表**：搜索改变可见行、切视图换一份列表、归档 / 恢复 / 删除后行消失，看不见的选中项都要退掉（`pruneSelection`）——留着就是看不见却会被批量操作命中的幽灵选择。切视图保留形态本身（用户切过去多半接着挑），只清选择。
- **「全选」是翻转**：还没全选就选中全部，已经全选就取消全部；作用范围是**当前可见且可选**的那些行（搜索是筛选、不是另一次选择）。
- **删除两段式**：与行内垃圾桶同一条口径（`DELETE_ARM_MS` 武装 3 秒，确认文案带影响条数）；同一时刻只留一个待确认目标，改选择或切视图即作废确认。
- **恢复归档**走 `workspace/unarchiveSession`（与归档同一个 `WorkspaceArchiveValue`）：本地先把 id 从 `archivedSessionIds` 退掉让列表立刻回到普通视图，权威值仍由 `workspace/follow` 的 `archived` 增量确认——与归档是同一条链路，不另设一套。
- 批量操作对选中项**逐条**发既有的单条消息（`archiveSession` / `unarchiveSession` / `deleteSession`），不新开批量端点。单项与批量删除都通过 `sessionRow` 查找会话，包含旧列表未覆盖的其他根目录；仍执行安全会话 id、目录包含性、运行状态和窗口查看状态的检查。

## 验证与未覆盖边界

回归入口：blankSessionReuse、blankRestoreRace、blankPresetAdopt、blankSessionNoop、emptyComposer、workspaceDirRepick、historyDirectory、directoryPathKey、sessionSelection、composerSessionDraft、commandNode、unreadMarker。覆盖空壳参与状态、首条消息归属与本地 blank 位折算、恢复让位、认领与预设兜底、**停在空壳上点「+」完全 no-op**（改过模型 / 思考强度 / 权限 / 预设、留着草稿附件与失败回显、有标题 / 计划 / 目标 / 自动化任务、断连、模型目录不可用各档都不发一帧也不发一笔 RPC，反复点仍是同一条壳）、无壳 / 内容会话照旧落壳（接回现成壳要一次指名认领，否则真新建）、**空壳由窗口共享**（第二个窗口接回同一条、两个窗口并发也只落一条、共享之后各自点「+」都是 no-op）、落壳期间关窗收手、历史列表的占用锁、运行状态对账、逐项未读持久化、删除清理与多选判据，不替代全部跨宿主时序验证。

- 不跨独立 VS Code 窗口登记“哪个窗口打开哪条会话”；要支持它，须在 supervisor 共享通道增加登记协议。
- 不与浏览器 dsh web 同步未读：服务端没有这项客户端状态。
- 上述未实现能力是明确范围边界，不应凭现有回归宣称全局未读一致。
