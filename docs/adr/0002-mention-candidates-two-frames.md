# `@` 候选分成两条帧：文件先发、对话候选后到

`@` 列表的两个候选源在服务端的成本差**三个数量级**：

| 源 | 服务端做什么 | 本机实测（339 条会话） |
|---|---|---|
| 文件（`fileReferences/list`） | 一次 `readdir`（目录查询；见 harness `context/file-reference-local` 的 `listDirectory`） | **0.1ms** |
| 对话（`sessionReferenceResolver/candidates`） | `sessionQuery.listSessions` → 遍历**所有**项目目录、**每个**会话 stat + 打开 + 读头部（zstd 首帧解压） | **130ms 以上** |

改造前宿主用一次 `Promise.all` 把两者合成一条 `files/list` 帧，于是「切进一个只有
几个文件的目录」也要等完整趟全语料扫描——用户 2026-09-25 报的「@ 列表切换目录
感觉慢」正是它。同一天还有三处白烧：下钻 / 回上一层各自又多发一次查询（一次导航
发两遍）、选中候选后发一次没人看的清空查询、`/` 命令目录跟着每次敲字重取。

## Decision

1. **两条帧**（`shared/ipc.ts`）：`files/list` 只有文件，`files/sessions` 只有对话
   候选，各自带 `query`。宿主在两个 RPC 都发出去之后，**文件那一帧先发**（只串发帧
   顺序，RPC 仍并行），对话候选回来再发它自己那一帧。界面侧 `files/list` 只换文件
   那一半、旧的对话候选先留在屏上（官方的 stale-while-revalidate，
   `ui-input-trigger` 的 `menuReduce`），`files/sessions` 的 `query` 与当前列表不一致
   就**整帧丢掉**（防「文件是这一层的、对话是上一层筛出来的」）。
2. **每次查询作废上一次**（`controller.menuQueries`）：句柄同时是取消入口与
   「这一次还是不是当前那一次」的判据。这不只是丢掉回来的结果——网关把客户端断开
   接到请求的 `signal` 上（harness `client/connection` 的 http-bridge），会话候选
   扫描每一步都有 `throwIfAborted`，所以作废能真正省下服务端的活。窗口下线时作废
   并清表。
3. **界面侧只有一个重取点**：`@` 的重取由「查询串变了」那个 effect 独占
   （`composerCompletion.tsx`），导航、选中都不再自己发帧；`/` 命令目录与查询串无关
   （过滤在本地做），只在命令通道打开时取一次。
4. **对话候选只在工作区根目录列**（用户 2026-09-25 口径，**刻意偏离官方 `@` 源**：
   官方拿查询串去筛历史对话，进了目录也照样列）。查询串里一旦出现分隔符，宿主**连查
   都不查**（那趟是全语料扫描，查了也只能丢掉，顺带把进目录这一路的服务端成本降到零），
   界面在**渲染**那层同步判掉（`rankCandidates` 的 `isDirectoryQuery`）——只靠宿主不发
   那批帧就会出现「先进目录、对话条目过一会儿才消失」，因为帧要等一个往返。

## Consequences

- 切目录的感知延迟从「对话候选的往返」（百毫秒级）变成「目录 readdir 的往返」
  （几毫秒级）。
- 敲一个长路径不再压出一串并发的全语料扫描：作废 + 单次重取把服务端那趟活收敛成
  最后一次。
- 界面必须按 `query` 丢旧批次：宿主已经作废了旧查询，但两批回答的先后本来就无保证，
  两道防线都要有（断言见 `scripts/mentionCandidates.test.ts`）。
- 对话候选短暂「属于上一次查询」这件事是**刻意的**：清掉会让列表先塌一块再长回来。
  要改这条先看官方 `menuReduce` 的 stale-while-revalidate。**只限根目录**：进了目录
  之后对话那一组一个都不出现（第 4 条），所以「留着旧批次」看到的只会是根目录时代
  的历史对话，不会混出「文件是这一层的、对话是目录外的」。
- `files/list` 帧不再带 `sessions`：它是界面认「这是哪一次查询」的锚，对话候选那一帧
  永远排在它之后；进了目录时那一帧**根本不发**（状态里留着上一次根目录查询的结果，
  回到根目录时先显示它、再被新一批替换）。
- 偏离官方的那一条（只在根目录列对话候选）是**产品口径**，不是实现取巧：要恢复官方的
  「按查询串筛历史对话」，得同时去掉宿主与界面两侧的判据，否则会一半列一半不列。
