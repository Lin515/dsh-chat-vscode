# 「生成完毕未读」只有一个来路：离开时它正在生成

## Context

历史会话列表里那条蓝标题（`unread`）此前是「观察到某条会话从运行中落到结束、且此刻没人在
看」点亮的（官方 `SessionSummary` 里**没有**这个概念，它是本扩展自己的状态）。那条口径会把
**别处跑起来（另一个窗口 / 浏览器里的 dsh web / CLI）、本窗口从没打开过**的会话也点亮
——「离开」这个动作本身反而不在判据里。用户 2026-09-24 定了现在的口径：

> 仅当**离开时它正在生成**、且没有任何会话窗口开着它，才留一个标记；该实例的生成**完成**时
> 再判一次有没有窗口开着它——没有就落款未读。标记一直留到用户回来看过它。

判据落在 `controller` 的 `leftGeneratingSessionIds`（内存）+ `unreadSessionIds`（持久化），
兑现点在 `settleRunningChange`。

改口径之后仍然有「明明已读却还亮蓝」的残留。真机日志与会话日志对拍定位到两条链路：

1. **收尾的权威值先到、durable 收尾后到**：`api-session/status`（`$events`）与本轮的
   `turn/end`（`session/follow`）是两条流。状态位说「不在跑」的那一刻，本地适配器还认为
   本轮开着（等审批 / 等提问那种长轮次里这是**唯一的**肯定证据），于是它被
   `acceptSessionStatus` 拒收（这条规则保的是「乱序的旧 `false` 骗掉停止按钮与
   `waitUntilIdle`」）。随后 durable 收尾到了，却**只改了域**——会话列表那一行没人纠正。
   结果：列表显示「生成中」，离开时 `isSessionGenerating`（域 **or** 行）据此记了离开标记，
   下一次列表刷新把那一行翻回 `false` 时结算成未读。真机上见过「会话早已收尾、几十秒后
   离开仍被判为离开生成中」。
2. **多窗口整份覆写**：未读集合存在 `globalState`（跨窗口共享，且**不跨窗口实时同步**），
   而写入是**整份数组**。持旧副本的窗口下一次写盘会把别人已经清掉的旗标写回来——重载之后
   蓝标题「复活」。此外旧的整份集合里还留着改口径之前点亮的旗标（旧规则无法用新规则解释），
   以及已删除会话的旗标（它已从列表消失，那条旗标永远不会被清）。

## Decision

1. **durable 的「在不在跑」同时落到会话列表那一行**（`SessionAdapter` 的回调里把
   `running` 帧交给 `setSessionRowRunning`）：列表与域从此同一个来源，收尾后不再有残留的
   「生成中」。
2. **被拒收的权威状态位记账复查**（`pendingStatuses`）：拒收时把值记下，等「本地有没有开放
   轮次」这件事变了（域被回收，适配器随之消失）再重判一次。拒收 ≠ 忘记。
3. **未读一个会话一把键**（`unreadStore.ts` 的 `unread:<会话 id>`，清 = 删键）：窗口只写
   自己刚改过的那一条，整份覆写这条通道就没有了。
4. **旧口径那份整份数组启动时作废**：旧规则点亮的会话无法用新规则解释，宁可少亮一次也不留
   假蓝。**删除 / 归档会话时清掉旗标**：那条蓝否则永远不会被清（删除的会话连归档列表都不进）。

## Consequences

- 历史列表那一行现在是 durable 真相的镜子：一轮收尾后它立刻回落到空闲，不再需要等一次列表
  刷新。代价是**适配器与中继都可能给它赋值的**地方多了一条对账（断言见
  `scripts/unreadMarker.test.ts` 的 ⑪⑫⑬）。
- **刻意保留**的一条例外：本地有开放轮次（等审批 / 等提问的长轮次，服务端此刻没有活跃
  attempt）时，服务端那句「不在跑」不被采信——所以那种状态下**会话视图显示「生成中」**，
  此时离开照样记标记（用户是在「界面说它在生成」的状态下离开的）。修的是「收尾后残留」，
  不是这条例外。
- **没做**的两件事：①跨窗口的「有没有别的窗口开着它」——每个 VS Code 窗口是独立扩展宿主，
  要判它得在 supervisor 那条共享通道上加「哪些窗口开着哪条会话」的登记；②与浏览器里的
  dsh web 同步——未读是**客户端**状态（扩展自己的 `globalState`），服务端没有这个概念，
  同步无从谈起。两者都不在当前口径里。
