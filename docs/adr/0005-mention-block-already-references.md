# `@` 列表何时弹：这一块已经能引用到内容就不弹

## Context

`@` 列表的候选来自**服务端按查询串**做的两件事：列目录（`fileReferences/list`）与筛历史
会话（`sessionReferenceResolver/candidates`）。后者按**会话 id / 工作目录 / 标题**做大小写
不敏感的子串匹配（harness `context/session-reference` 的 `listCandidates`），所以
「在输入框里打 `@` + 会话 id 就能匹配到那条会话」本来是成立的。

2026-10-10 那轮口径把 `@` 的触发收成两条入口（裸 `@`、以 `/` 或 `\` 结尾的目录块），
本意是治「光标一移进已经写好的引用（`@src/a.ts`、`@[标题](dsh-session:…)`）就冒出候选
列表」。副作用是**任何有内容的普通块都不再触发**：打会话 id / 名字片段一条候选都不出来
（用户 2026-10-11 报的现场）。

「已经写好的引用不该弹」与「在检索会话要弹」用**形状**分不开：`@session-4be424ed-…`
与随手打的 `@web` 长得一样，而它们要的结果相反——只有**内容**（这个块指向的东西到底
在不在）分得开。

## Decision

1. **触发判定回到「块里有内容就触发」**：光标落在哪个 `@` 内容块里（`findTrigger` 的
   `mentionBlockAt`）就以**整块**为查询串——查询串与光标在块内的位置无关（这条是
   2026-10-10 修对的，保留）。
2. **弹不弹由宿主的「这一块能不能引用到内容」判**（用户 2026-10-11 口径，逐字：
   「如果光标所在对应的 `@` 块已经能够引用到有效内容（文件存在或会话存在）……那么就不
   弹出 `@` 列表框，否则就要弹出」）。判据在 `controller.mentionResolves`：
   - **路径**：去掉末尾的行号区间（`formatFileMentionWithLines` 的产物，`@src/a.ts#L12-L40`
     指的仍是那个文件），绝对路径原样、相对路径按**会话工作目录**解析，`stat` 得到才算在；
   - **对话引用 token**（`[标题](dsh-session:…)` 或裸 `dsh-session:…`）：解出会话 id，看
     这条会话还在不在（`this.sessions`）。
     打一个**裸会话 id**（`@session-…`）不算——它不是服务端认的引用形态
     （`parseSessionReferenceText` 只认上面两种），那仍然是在检索会话；
   - **拿不到证据**（没有工作目录、路径解析不了、`stat` 报未知错误）一律按「不抑制」：
     宁可多弹一次列表，也不能因为判不出来就把用户的候选整块按住。
3. **浏览入口不做判定、恒弹**：裸 `@` 与以 `/` 或 `\` 结尾的路径是「进去看这一层」的意思，
   目录在不在都要能进去（不存在的目录列出来是空表，比什么都不弹更说明问题）。
   `shared/mentions.ts` 的 `isBrowseQuery` 是这条判据的唯一出处，宿主与界面共用。
4. **判定随 `files/list` 那一条帧回来**（`resolved`，与 `query` 同一批），抑制时宿主
   **一个查询都不发**、当场回一条空帧：既省下那一趟（诊断「光标在已有引用里」时每敲一个
   字符白扫一次全语料），也让界面**立刻**拿到判定。
5. **判定还没到就先不弹**（界面侧 `mentionSuppressed`）：宁可晚一两帧，也不能在光标移进
   一条已有引用时先闪一个列表出来（那正是 2026-10-10 要治的现场）。浏览入口不吃这一条。
6. 旧宿主不发 `resolved` 时按 `false` 收：退回「一律弹列表」的旧行为，不做抑制
   （宿主与 webview 两份产物不同步时只会多弹，不会少弹）。
7. **焦点重新进入输入框算一次新的编辑动作**（`onFocus`）：清掉「已关闭」记忆（ESC 关闭 /
   选中一条之后那份「同一次编辑动作里先别重开」的记忆）并重算触发词。少了它有个死结：
   记忆按（文本, 光标）匹配，而从框外点回来时光标常常一个字没动（点在文本右侧的空白处
   就是末尾那一格），记忆仍命中 → 那次探测直接返回、列表永远不出来，用户得先在框内挪
   一下光标（位置变了才让记忆失效）才弹；而触发词只在事件里重算，宿主把焦点还回来那种
   **纯焦点**不重算，同样一帧都不弹（用户 2026-10-11 报的现场）。

## Consequences

- 「打 `@` + 会话 id」这条路恢复：列表按 id / cwd / 标题匹配到那条会话，选中插入规范
  token（`@[标题](dsh-session:…)`）。
- 光标移进已有引用不再弹列表，而且**不是靠形状猜**：文件被删 / 被改名之后它引用不到内容，
  列表会照常弹（那种引用本来就需要用户重选一条）。
- 盘上已有、但**不带尾分隔符**的目录（`@src`）也会被抑制：想浏览它得写 `@src/`
  （第 3 条：带分隔符的路径永远弹）。这是用户口径的直接推论，不是实现取巧。
- 判定未到的那一两帧里列表不显示。代价可以量：抑制的块不查（子毫秒级回帧）；不抑制的块
  等的是**索引**查询——官方 `file-reference-local` 只有每个工作区的第一次要遍历一遍，
  之后陈旧索引当场作答（`search.ts` 的 `indexFor`）。
- 这条路恢复之后，**普通片段也会重新触发模糊查询**（`@web` 这种）。这是 2026-10-10 之前
  的行为，也是服务端筛会话的入口；不想要它就得把「检索会话」交给另一条通道——那是另一个
  决定，别顺手改这条。
- 界面与宿主对「浏览入口」的判据必须同源（`isBrowseQuery`）。两边各写一份正则，迟早会
  出现「界面不等判定、宿主却判了」或者反过来。
