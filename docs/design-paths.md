# 文件路径：目录基准、记录身份与执行世界

修改文件打开、悬停、工具产物、改动清单、交付卡片或正文图片读取前读本文。投影与水位见[投影设计](<design-projections.md>)，呈现见[消息设计](<design-messages.md>)，读取权限与资源限制见[安全边界](<design-security.md>)，核验版本见[兼容规则](<dsh-compat.md>)。

**本文规定对齐官方 DSH Web 的目标设计，不代表代码已经完成。** 文件定位包含三个不可合并的问题：相对路径以哪个目录解释、历史操作记录了哪个目标、由哪个文件系统读取它。仅把基准目录换对，不能解决远端同名路径读错的问题。当前缺口与实施顺序见「实现状态与实施顺序」。

## 目录身份与职责

- **创建目录**：会话 header 的 `cwd`，创建后不随执行目录变化。工作区注册表通过执行世界的 `fs.realpath(header.cwd)` 比较工作区 `path`，推导会话归属；「会话所属目录」不是第三份可独立修改的会话字段。注册表的规范化身份与 header 的原始拼写不必相同。
- **执行目录**：`workingDirectory` 投影，类型为 `string | null`，从 `header.cwd ?? null` 初始化，由 `working-directory/change` 更新。执行侧取得有效目录时还可能使用部署默认值或恢复失效目录，因此两者不同不只可能来自用户主动切目录。
- **执行世界**：DSH 文件系统 provider 所代表的路径空间及访问策略；可能是本机、WSL、容器或远端。扩展宿主的本机文件系统不是它的默认替代品。

| 消费者 | 目录规则 |
|---|---|
| 文件工具与 `present` 的相对输入、新建终端、子代理继承、项目指令、技能发现、当前 `@` 查询 | 执行侧的有效执行目录；显式参数与既有进程另按各自契约 |
| 普通正文相对链接、没有记录值的旧文件引用 | 会话创建目录，不追随最新执行目录 |
| 会话工作区归属、存储 / 归档、sandbox workspace-write 根 | 创建时确定的身份或策略，不因执行目录迁移 |
| 改动清单 | Host 为该清单确定的固定根；根内路径相对，根外路径绝对 |
| 工作区文件 API 的相对输入 | `header.cwd ?? sandboxPolicy.workspaceRoot`，由服务端确定 |

**不全局切换到执行目录，不维护目录时间线，不探测多个目录挑选存在的同名文件。** 历史操作的准确目标由执行时的记录值承担。改变会话执行目录不改变既有进程的 cwd，也不扩大已有权限。

## 文件资源身份与访问权威

### 会话范围与路径形态

普通文件资源至少保留「连接身份、会话 id、路径」；带轮次坐标的资源还保留其事件坐标。不同连接或会话下同一个路径字符串不能共享内容、存在性结论或打开结果。行号是导航参数，不是另一个文件身份。

官方 `fileAddressFor` / `sessionFileAddress` 把相对路径与创建目录内的绝对路径放进会话范围地址；根外的绝对路径仍保留绝对形态，但不丢会话身份。扩展不必复刻 Web Sidebar 的地址格式，必须保留这层语义。

- 绝对形态按执行世界识别（POSIX、Windows 盘符或 UNC），不能用扩展宿主平台的 `node:path.isAbsolute` 替远端作结论。绝对记录值不重新拼目录。
- 普通相对输入按创建目录交给执行世界解析；不使用当前 VS Code 工作区、扩展进程 cwd 或最新执行目录兜底。
- 缺创建目录时，官方客户端保留原始相对拼写，服务端工作区 API 可使用其契约规定的 sandbox 根。扩展不能据此声称已知绝对位置；需要绝对路径的动作应等待权威结果或明确不可用。
- 官方 `resolveWorkspacePath` 只做字符串拼接，最终规范化由 provider 完成。悬停可以展示派生拼写，但不能用本机消点、realpath、统一转小写等方式改变远端文件身份；终端标签的显示规范化另见下文。

### 读取、打开与原生动作

文件内容、存在性及规范化结果以 DSH 执行世界为权威：文本和字节读取遵守目标版本 `workspaceFiles` 契约；正文媒体读取遵守已认证的 `/api/file` 路由；轮次对比取 Host 提供的快照与 hunk。已打开文件的关联资源另遵 `readBytes` 的 `baseFile` 契约，相对资源由服务端按基文件所在目录解释，不误套会话正文的创建目录规则。端点形状在实施时核对目标版本产物，不从本地 API 档案猜载荷。

VS Code 可以继续作为展示容器：远端内容用带连接与会话身份的资源承载，不能把远端绝对路径直接转成 `vscode.Uri.file`。本地编辑器、Git 扩展、系统浏览器和资源管理器仅在已验证映射到同一文件系统时使用本机路径。路径为本机形态、同名目录在本机存在、端点是 loopback，都不能单独证明该映射；`@` 本地发现的启发式闸门也不是证明。

官方原生打开先由 Host 验证目标及文件系统到 Host 的映射。扩展对原生打开 / reveal 应采用同等可验证的能力；能力不可用时明确拒绝或提供显式下载副本，不能静默打开另一世界的同名文件，也不能把下载副本冒充原件。用户上传前的本地附件原件属于已记录的本地来源，仍按[附件设计](<design-attachments.md>)处理，不和模型输出路径混用。

存在性保持 `present` / `absent` / `unknown`：只有权威文件系统明确报不存在才算 `absent`，权限拒绝、离线、未知错误及未验证映射均不等于删除。读取失败不回退本机同名文件。异步读取、缓存与迟到回帧均绑定原连接和会话，切换后不能写入新范围。

## 工具路径：按消费者分别取值

第一方文件工具用 `ctx.fs.processPath(target)` 在结果元数据记录执行时的绝对目标；终端以 `meta.cwd` 记录实际目录。外部工具、旧结果或异常数据不保证满足该形状。公共判据 `recordedAbsolutePath(meta, field)` 只接收绝对字符串，不把无效记录值按当前目录补齐。**工具行、产物登记和终端标签的回退不同，不合并成一条三档规则。**

### 工具行的打开目标

对齐官方 `toolRowModel`：

1. 先从该工具的调用参数派生 `argumentPath`。没有参数路径时，不仅凭孤立的 `meta.path` 为该行新增文件动作。
2. 已结算且 `meta.path` 为绝对路径时，优先用记录值。
3. 没有有效记录值时，仅在参数本身绝对，或调用已成功结算且 `parentCallId` 缺失（根调用）时，允许使用参数路径。
4. 运行中、失败或嵌套调用的相对参数不成为打开目标。记录值有效时仍遵守前述优先级，不另加成功条件。

参数原文用于摘要与输入展示，打开目标单独保存。嵌套调用的身份必须保留到判据执行处，不能在适配器中提前丢失。read 的行号仍取该次结果；diff 标题可以显示原参数，不能反过来把显示标题当成打开目标。

### 本轮产物登记

仅对官方 `mutationPath` 认可且参数完整的第一方变更调用（`write`、`edit`、`str_replace_editor` 的变更命令）使用 `mutationResultPath` 语义；失败或中断不登记为成功产物。官方产物归约消费根级 `tool/call`，PTC 分发子调用不独立进入该定义；不能把展开后的任意子调用重新计为根产物。该规则不直接套给任意工具或批量 OPS 结果。

| 结果元数据 | 产物路径 |
|---|---|
| 不是记录对象，或没有自有 `path` 键 | 回退 `argumentPath`，包括旧结果的相对拼写 |
| 自有 `path` 是绝对字符串 | 使用记录值 |
| 自有 `path` 存在但无效（含相对、空串、非字符串） | 仅保留本身绝对的参数；参数相对则不登记 |

例如成功根调用的参数为相对路径、`meta.path` 也是相对路径时，工具行可按自己的回退规则保留动作，产物却不登记。这是官方两处判据的差别，不应为追求统一而改写。

产物操作保留 `path` 与发生替换时的 `argumentPath`，并保留所属轮次及事件 `seq`。展示路径可去重，但不能因此丢掉同一路径的多个参数别名，也不能把同一参数在不同执行目录命中的两个目标合并掉。`present` 的 `deliverables/presented.files[].path` 在服务端规范化为绝对路径，显式交付仍是独立来源，不被产物去重吞掉；交付项同时保留其事件 `seq` 与原始 `index`，原生动作由 Host 按坐标重取记录并验证目标，不以客户端回传路径代替交付身份。

### 终端目录标签

对齐官方 `terminalCardModel`，在卡片本身满足展示条件的前提下：

- 已结算结果优先采用绝对 `meta.cwd`，原样保留记录值，不用当前执行目录重算。
- 无有效记录值且是已结算的根 shell 调用：绝对 `workdir` 用于显示，相对 `workdir` 拼创建目录，省略则显示创建目录；只对参数派生标签消去 `.` / `..`。
- 运行中或嵌套调用只能从请求取得绝对 `workdir` 标签，不替相对或省略参数猜目录；已结算 `terminal_send` 等调用也不借 shell 的创建目录回退。
- 根 shell 的旧结果缺创建目录时，相对 `workdir` 规范化后仍可作为相对标签显示，省略则无标签。这只是显示，不是可读取的绝对目标。

## 正文引用与历史稳定性

普通 Markdown 文件链接按创建目录解释；目录变化后，手写相对链接仍可能指向非预期文件。这是官方边界，不以最新执行目录、目录时间线或存在性探测修补。

行内代码文件引用另有官方 `producedFileMentions` 的纠正机制：在当前轮次的产物 / 交付路径中累计精确匹配与 basename 匹配，再把成功操作中 `argumentPath` 精确匹配所对应的记录目标加入同一集合；**集合只有一个目标时才提供动作**。不是先匹配到的优先，也不允许跨轮次借别名。例如切目录后写入的 `src/a.ts` 可由该轮参数别名指向记录的绝对路径；若同一别名对应两个文件，就保持不可点击。

悬停与点击使用同一个已选目标，不各自重新推导；缺创建目录的原样提示不能冒充完整绝对路径。已发送的 `@` 引用不由当前查询目录追溯改写，有绝对来源时直接保留；其余按已有引用契约处理。`grep` / `glob` 相对执行时 workdir 的展示路径不自动升级为历史绝对定位依据。

## 改动清单与坐标

Host 为轮次 recorder 一次确定创建目录的规范化根。`durablePathOf` 对根内目标输出相对路径，对根外目标保留绝对路径；**固定根不代表清单只含根内文件，也不代表所有行都相对**。header 原始目录拼写与 realpath 后的根还可能不同，扩展不得靠本机 realpath 补证据。

清单身份是连接、会话、事件 `seq` 与原始 `index`；路径比对只是展示关联与防错检查，不能替代坐标。官方 `handleChangesOpen` 由 Host 查坐标、取清单根，再通过执行世界 `workspaceFiles.stat` 验证文件。扩展关联产物与清单时须容纳绝对及相对两种路径，只有能证明同一目标时才挂坐标，不能用 basename、全局小写或最新执行目录猜中一行。

对比内容不得用扩展本机同名文件回填。需要当前文件补上下文时，从同一执行世界读取并按既有 hunk 判据核对；不具备读取能力就保留快照片段。清单或对比已不可用时可以退回同一执行世界的普通文件查看；本机 Git 回退仍须先证明映射，不得静默越过这道边界。

## 正文图片的路径与权限

相对图片路径按创建目录解释，绝对图片路径保留原目标；不跟随执行目录，缺创建目录时也不回退 VS Code 工作区。官方 `fileMediaUrl` 拒绝非绝对、UNC 与控制字符路径，生成已认证的 `/api/file` 请求；服务端用 `ctx.fs` 解析与读字节，并使用部署的图片字节限额。

**创建目录不是媒体读取白名单。** 官方媒体路由不以路径是否在创建目录内或扩展名是否为图片来授权。根外绝对图片能否读取由执行世界 provider 的访问策略决定；这不等于绕过认证、操作系统权限或任意 provider 的限制。浏览器可否显示某媒体类型与文件读取权限是两件事。

当前扩展的本机读取、创建目录包含性、8 MiB / 24 张与扩展名表属于尚待迁移的实现限制，不能宣称完全对齐。实施时应整体接上受认证的执行世界读取和服务端限额，再移除不等价的本机规则；不能仅删除包含检查、扩大本机读盘范围。图片加载的中间失败与最终降级继续按[安全边界](<design-security.md>)处理。

## 实现状态与实施顺序

本次只修正设计，不改变代码与发布基准。既有临时移交文档是历史方案，冲突处以本文为准，不再把长期实施规则放在临时文档中。

| 消费面 | 当前状态与待实施内容 |
|---|---|
| 服务端目录与记录值 | 官方已提供创建身份、执行目录、`meta.path` / `meta.cwd` 与规范化交付路径；扩展不可改写这些语义 |
| 扩展路径基准 | `cwdOf` 多个打开入口取创建目录，但界面悬停仍优先传执行目录；图片缺目录还回退 VS Code 工作区，未完成一致化 |
| 工具行与产物 | 仍主要取调用参数；需保留结算 / 嵌套身份，分开实现记录值与回退判据，产物增加操作别名信息 |
| 终端标签 | 尚未消费记录 `meta.cwd` 及分状态的回退规则 |
| 正文行内引用 | 现有精确 / basename 匹配不足；需累计参数别名并统一判歧义 |
| 清单关联与对比 | 已消费 Host 坐标 / hunk；仍需核对根外路径、规范化身份及回填读取所在世界 |
| 文件访问与图片 | 当前本机 `stat` / `Uri.file` / 图片 `readFile` 不能覆盖远端；执行世界资源与可验证本机映射尚未贯通 |

按以下边界分步实施，各步完成不等于整体对齐：

1. 在共享纯逻辑与适配器中落实工具行、产物、终端的独立判据，保留打开目标、参数别名及来源；实时结算与历史重放走同一路径。
2. 统一普通链接、悬停及清单关联的目录来源，不动执行目录查询、会话归属、沙箱或既有进程。
3. 在宿主文件访问边界集中承接执行世界的读取与错误、会话资源身份及原生能力验证；迁移打开、图片、存在性分类与 diff 回填，禁止各入口自行落到本机。系统保存对话框的默认目录属于本地下载目的地，不是执行世界读取基准。
4. 联调芯片、正文、交付、改动行、附件来源与原生动作，分别验证同机与异世界情形，再更新实现状态。已设计未实施事项以上表与本实施顺序为长期依据，不依赖本地待办文件或临时移交，也不标作未决定的产品候选。

## 验收要求

现有 `fileChange`、`fileLinks`、`produced`、`toolView`、`toolCard`、`changesCard`、`localImages` 与 `imageHydrate` 是扩充入口，不代表下列场景已被覆盖。

- **目录错位**：创建目录 A、执行目录 B，分别存在同名文件；工具行 / 产物使用指向 B 的记录值，正文绝对图片引用 B 时也不读 A 的同名副本。继续切到 C、重连及历史重放后结果不漂移；普通手写相对链接与相对图片仍遵创建目录边界。
- **取值矩阵**：运行中 / 成功 / 失败 / 中断、根 / 嵌套、绝对 / 相对参数、缺 meta / 缺自有键 / 无效字段 / 绝对记录；工具行与产物分别断言，不用一个函数覆盖两者。
- **终端标签**：记录 `meta.cwd` 优先，旧根调用各档回退，嵌套与运行中不猜，缺创建目录仅保留相对展示；失败等不满足卡片条件的结果仍按官方降级。
- **参数别名**：完整相对参数、唯一 basename、多个别名指向一文件、同名 / 同别名指向多文件、跨轮次隔离；悬停与打开选同一目标。
- **清单身份**：根内相对与根外绝对共存，header 拼写与规范化根不同，坐标只绑定唯一目标；读取不可用时不能从另一世界补上下文。
- **执行世界隔离**：本机与远端同形同名但内容不同，Windows / POSIX 混合客户端，断线、权限拒绝、缺 header.cwd 与切连接迟到响应；不得误读本机、误报删除或复用错误缓存。
- **媒体与原生动作**：根外绝对图片由 provider 裁决、相对图片创建根、UNC / 控制字符拒绝、服务端超限、图片异步恢复；未经验证的本机打开 / reveal / 浏览器动作不可用，显式下载只声明为副本。

走真实文件系统的夹具使用平台原生临时目录；跨平台路径语义使用纯字符串或 provider 替身。新增离线测试登记到脚本构建入口，常规验证与真实探针批准仍遵守[AGENTS](<../AGENTS.md>)。
